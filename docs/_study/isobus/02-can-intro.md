# CAN 통신 입문

::: info 학습 목표
- CAN이 왜 만들어졌고 어떤 표준(ISO 11898)으로 정리됐는지 설명할 수 있다.
- CAN이 쓰이는 분야를 예로 들 수 있다.
- 멀티마스터, 메시지 기반 브로드캐스트, 중재가 무엇인지 쉬운 말로 설명할 수 있다.
- 두 메시지가 동시에 나가려 할 때 ID를 보고 어느 쪽이 먼저 나가는지 판단할 수 있다.
- CAN과 LIN, FlexRay, Ethernet 같은 다른 통신 방식의 차이를 비교할 수 있다.
:::

::: tip 시작하기 전에
- 먼저 읽을 장: [1장 통신의 기초](/study/isobus/01-communication-basics)
- 이 장에서 처음 나오는 말
  - CAN: 자동차와 농기계의 ECU들을 선 두 가닥으로 잇는 직렬 통신 방식
  - 노드: 버스에 연결된 장치 하나. 이 장에서는 ECU와 같은 뜻으로 쓴다
  - 메시지 ID: 메시지가 어떤 내용인지 알려 주는 번호. 값이 작을수록 우선순위가 높다
  - 중재(Arbitration): 두 노드가 동시에 보내려 할 때 누가 먼저 보낼지 정하는 과정
  - Dominant와 Recessive: 버스의 두 상태. 0이 Dominant(우세), 1이 Recessive(열세)다
:::

도로가 하나뿐인 마을에서 여러 사람이 동시에 차를 몰고 나오면 누군가는 양보해야 한다. CAN은 수십 개의 ECU(전자 제어 장치)가 선 두 가닥을 함께 쓰면서도 서로 부딪히지 않게 해 주는 규칙이다. 이 장은 CAN이 어떻게 태어났고, 어떤 규칙으로 양보와 오류 확인을 해내는지 큰 그림으로 본다. 세부 동작은 3~7장에서 하나씩 깊이 들어간다.

## 1. CAN이란

이 절에서는 CAN이 어떤 문제를 풀려고 만들어졌는지, 그리고 어떤 표준 문서로 정리돼 있는지 본다.

<strong>CAN(Controller Area Network)</strong>은 1986년 <strong>Bosch(보쉬)</strong>가 개발한 직렬 통신 프로토콜이다. 이름 그대로 차 안의 제어 장치(Controller)들을 잇는 좁은 범위(Area)의 통신망(Network)이다. 원래 자동차 내부의 여러 ECU를 적은 배선으로 연결하기 위해 설계되었다.

당시 자동차 전장 시스템(차에 들어가는 전기·전자 장치)이 복잡해지면서 배선 무게만 50~60kg에 달했다. 1장에서 본 개별 배선 방식의 한계다. Bosch는 이 문제를 해결하기 위해 2선 버스 하나로 모든 ECU를 연결하는 방식을 고안했다.

1991년 Mercedes-Benz S-Class에 처음 양산 적용되었고, 이후 <strong>ISO 11898</strong>로 국제 표준화되었다. ISO(국제표준화기구)가 펴낸 11898번 표준이라는 뜻이다.

![1986년 Bosch의 CAN 프로토콜 발표, 1991년 Mercedes-Benz S-Class 최초 양산 적용, 1993년 ISO 11898 국제 표준화, 2003년 J1939 기반 ISOBUS(ISO 11783) 완성, 2012년 Bosch의 CAN FD 규격 발표를 실제 연도 간격대로 놓은 연표](/images/study-isobus/02-can-timeline-light.png)
![1986년 Bosch의 CAN 프로토콜 발표, 1991년 Mercedes-Benz S-Class 최초 양산 적용, 1993년 ISO 11898 국제 표준화, 2003년 J1939 기반 ISOBUS(ISO 11783) 완성, 2012년 Bosch의 CAN FD 규격 발표를 실제 연도 간격대로 놓은 연표](/images/study-isobus/02-can-timeline-dark.png)

연표의 J1939는 트럭·버스 같은 상용차에서 CAN 위에 얹어 쓰는 통신 규칙이고([8장](/study/isobus/08-j1939-intro)), ISOBUS는 J1939를 바탕으로 농기계용으로 만든 표준이다. CAN FD는 CAN을 더 빠르고 더 많이 보낼 수 있게 확장한 방식이다([7장](/study/isobus/07-can-fd)).

### CAN 표준 체계

ISO 11898은 여러 부(Part)로 나뉘어 있고, 부마다 다루는 범위가 다르다.

| 표준 | 내용 |
|------|------|
| ISO 11898-1 | 데이터 링크 계층 (프레임 구조, 에러 처리) |
| ISO 11898-2 | 고속 물리 계층 (최대 1 Mbps) |
| ISO 11898-3 | 저속 내결함성 물리 계층 (최대 125 kbps) |
| ISO 11898-5 | 저전력 모드 (슬립/웨이크업) |

표의 말을 풀면 다음과 같다.
- 물리 계층: 전선, 전압, 커넥터처럼 0과 1을 전기 신호로 실어 나르는 부분이다. [3장](/study/isobus/03-can-physical)에서 본다.
- 데이터 링크 계층: 비트를 모아 프레임을 만들고 오류를 확인하는 부분이다. [4장](/study/isobus/04-can-data-frame)부터 본다.
- Mbps, kbps: 1초에 보내는 비트 수다. 1 Mbps는 초당 100만 비트, 125 kbps는 초당 12만 5천 비트다.
- 내결함성: 선 하나가 끊어지는 고장이 나도 통신을 이어 가는 성질이다.
- 슬립/웨이크업: 쉴 때 전기를 아끼는 잠자기 상태와, 거기서 깨어나는 동작이다.

ISOBUS가 쓰는 것은 고속 물리 계층(ISO 11898-2)이다.

## 2. CAN을 쓰는 곳

CAN은 자동차에서 시작했지만, 지금은 훨씬 넓은 분야에서 사용된다. 값싸고 튼튼하며 제때 동작해야 하는 제어 장치라면 어디든 쓰인다.

그림의 낯선 말 몇 개를 풀면 다음과 같다. ABS(Anti-lock Braking System)는 급제동 때 바퀴가 잠기지 않게 하는 브레이크 장치다. PLC(Programmable Logic Controller)는 공장 설비를 제어하는 산업용 컴퓨터다. GPS 자동조향은 위성 위치를 받아 트랙터가 정해진 줄을 따라 스스로 핸들을 돌리게 하는 장치다.

특히 <strong>ISOBUS(ISO 11783)</strong>는 CAN을 기반으로 농기계 전용으로 확장한 표준이다. 트랙터와 작업기(파종기, 방제기 등)가 브랜드가 달라도 서로 통신할 수 있다. 예를 들어 A사 트랙터의 운전석 화면으로 B사 방제기를 조작할 수 있다.

## 3. CAN의 핵심 특징

CAN이 자동차와 농기계에서 널리 쓰이는 이유는 네 가지 특징에 있다. 누구나 먼저 말할 수 있고(멀티마스터), 메시지를 모두에게 알리며(브로드캐스트), 동시에 말하면 중요한 쪽이 먼저 말하고(중재), 오류를 스스로 찾아낸다(에러 검출). 이 절에서 하나씩 본다.

### 3.1 멀티마스터 (Multi-Master)

기존 통신 방식은 마스터(명령하는 쪽)가 슬레이브(응답하는 쪽)에게 일방적으로 요청하는 구조가 많다. 슬레이브는 마스터가 물어볼 때까지 기다려야 한다. CAN에서는 <strong>어떤 노드든 원할 때 메시지를 전송</strong>할 수 있다. 사회자 없이 누구나 손을 들고 말할 수 있는 회의와 같다.

엔진 ECU도 먼저 보낼 수 있고, 브레이크 ECU도 먼저 보낼 수 있다. 단, 동시에 두 노드가 전송을 시도하면 <strong>중재(Arbitration)</strong> 과정을 통해 우선순위가 높은 메시지가 먼저 전송된다(3.3에서 본다).

### 3.2 메시지 기반 브로드캐스트

CAN에서는 "누구에게 보낸다"는 수신자 주소가 없다. 대신 <strong>메시지 ID</strong>로 내용의 종류를 나타낸다. 방송국이 채널 번호를 달아 방송을 내보내면, 보고 싶은 사람만 그 채널을 트는 것과 비슷하다. 이렇게 버스의 모든 노드에게 한꺼번에 알리는 전송을 브로드캐스트(broadcast)라고 한다.

예를 들어 ID `0x0CF004B4`(=217,056,436)라면 "엔진 상태 정보"를 의미한다고 약속한다. 이 메시지가 버스에 올라오면 버스에 연결된 모든 노드가 받는다. 각 노드는 자신이 필요한 ID만 골라서 처리한다.

아래 그림은 엔진 ECU가 ID `0x100`(=256)에 회전수 2000 RPM(1분에 2000바퀴)을 실어 보내는 장면이다.

![엔진 ECU가 ID=0x100, 데이터=RPM:2000 메시지를 CAN 버스에 올리면 계기판·변속기·ABS ECU가 모두 받는다. 계기판은 0x100이 필요해 RPM을 표시하고, 변속기는 기어 결정에 쓰며, ABS는 필요 없어 무시한다](/images/study-isobus/02-broadcast-filter-light.png)
![엔진 ECU가 ID=0x100, 데이터=RPM:2000 메시지를 CAN 버스에 올리면 계기판·변속기·ABS ECU가 모두 받는다. 계기판은 0x100이 필요해 RPM을 표시하고, 변속기는 기어 결정에 쓰며, ABS는 필요 없어 무시한다](/images/study-isobus/02-broadcast-filter-dark.png)

계기판 ECU와 변속기 ECU는 0x100이 필요한 메시지라 받아서 쓴다. ABS ECU는 필요 없는 메시지라 무시한다. 보내는 쪽은 누가 받을지 신경 쓰지 않는다. 그래서 받는 장치를 새로 붙여도 보내는 쪽을 고칠 필요가 없다.

방송 비유가 맞지 않는 점도 있다. ISOBUS에는 특정 장치 하나에게만 보내야 하는 메시지도 있어서, CAN ID 안에 받는 쪽 주소를 넣는 방법을 따로 정해 두었다. 이 방법은 [9장](/study/isobus/09-j1939-message)에서 본다.

### 3.3 우선순위 기반 중재 (CSMA/CD+AMP)

버스는 하나라서 한 순간에는 한 노드만 말할 수 있다. 두 노드가 동시에 말을 시작하면 누가 계속 말할지 정해야 한다. CAN은 <strong>CSMA/CD+AMP</strong> 방식을 사용한다.

- <strong>CSMA (Carrier Sense Multiple Access)</strong>: 여럿이 함께 쓰는 버스에서, 버스가 비어 있을 때만 전송 시작
- <strong>CD (Collision Detection)</strong>: 충돌 감지
- <strong>AMP (Arbitration on Message Priority)</strong>: 메시지 우선순위로 중재

두 노드가 동시에 전송을 시작하면, <strong>ID 값이 낮을수록 우선순위가 높다</strong>.

이 규칙은 버스의 전기적 성질에서 나온다. CAN 버스에서 0은 Dominant(우세), 1은 Recessive(열세)라고 부른다. 한 노드라도 0을 보내면 버스 전체가 0이 된다. 0이 1을 항상 이기는 셈이다. 각 노드는 ID를 맨 앞 비트부터 한 비트씩 보내면서 버스를 같이 읽는다. 자기는 1을 보냈는데 버스가 0이면, 더 우선순위가 높은 메시지가 있다는 뜻이다. 이렇게 ID를 비트 단위로 비교해 나가면서 먼저 Recessive(1)를 보낸 노드가 자동으로 물러난다.

```
노드A가 보내는 ID: 0 1 0 0 ...
노드B가 보내는 ID: 0 1 1 0 ...
                         ↑
                   이 비트에서 충돌
                   노드A(0=Dominant) 승리
                   노드B는 재전송 대기
```

위 예에서 두 노드는 첫 두 비트(0, 1)가 같아 계속 보낸다. 세 번째 비트에서 노드A는 0, 노드B는 1을 보낸다. 버스는 0이 되고, 1을 보냈는데 0을 읽은 노드B가 물러난다. 앞부분이 같다면 먼저 0이 나오는 쪽, 곧 ID 값이 작은 쪽이 이긴다.

충돌이 발생해도 <strong>전송 중인 메시지는 손상되지 않고</strong> 우선순위가 높은 메시지가 그대로 전송된다. 진 노드는 버스가 다시 비면 재전송한다. 이것이 CAN 중재의 핵심이다. 그래서 브레이크처럼 급한 메시지에 작은 ID를 주면 버스가 혼잡해도 먼저 전달된다. 전압 수준에서 왜 0이 이기는지는 [3장](/study/isobus/03-can-physical), 중재의 세부는 [5장](/study/isobus/05-can-arbitration)에서 본다.

### 3.4 높은 신뢰성: 에러 검출과 복구

CAN은 받은 데이터가 깨졌는지 스스로 확인하는 5가지 에러 검출 메커니즘을 내장한다.

| 에러 종류 | 검출 방법 |
|-----------|-----------|
| 비트 에러 | 전송하며 동시에 버스 읽기, 내가 보낸 값과 다르면 에러 |
| 스터프 에러 | 같은 비트가 6개 연속되면 에러 (5개 연속 뒤에는 반대 비트를 넣는다는 비트 스터핑 규칙 위반) |
| CRC 에러 | 수신된 CRC가 계산값과 다르면 에러 |
| 형식 에러 | 프레임 형식이 규격과 다르면 에러 |
| ACK 에러 | 수신자가 ACK를 보내지 않으면 에러 |

표의 말을 풀면 다음과 같다.
- 비트 스터핑: 같은 값이 5개 이어지면 보내는 쪽이 반대 값 비트를 하나 끼워 넣는 규칙이다. 받는 쪽이 박자를 놓치지 않게 하려는 것이다. 그래서 같은 값이 6개 이어지면 규칙이 깨진 것으로 본다. [4장](/study/isobus/04-can-data-frame)에서 본다.
- CRC: 1장에서 본 오류 검사용 숫자다.
- ACK: 프레임을 제대로 받은 노드가 잘 받았다고 표시하는 비트다.

에러가 감지되면 에러 프레임을 전송해 버스에 알리고, 자동으로 재전송한다. 에러 프레임은 방금 프레임이 깨졌다고 모두에게 알리는 특별한 신호다. 노드가 과도하게 에러를 일으키면 <strong>Bus-Off 상태</strong>로 전환되어 버스 보호도 된다. Bus-Off는 고장 난 노드가 스스로 버스에서 빠져 다른 노드의 통신을 방해하지 않게 하는 상태다. 자세한 동작은 [6장](/study/isobus/06-can-error)에서 본다.

## 4. CAN과 다른 통신 방식 비교

자동차와 농기계에는 목적에 따라 여러 통신 방식이 함께 쓰인다. 이 절에서는 농기계와 자동차 분야에서 자주 언급되는 통신 방식들과 CAN을 비교해 CAN이 어떤 자리에 있는지 본다.

| 항목 | CAN | RS-485 | LIN | FlexRay | Automotive Ethernet |
|------|-----|--------|-----|---------|-------------------|
| 표준 | ISO 11898 | EIA-485 | ISO 17987 | ISO 17458 | IEEE 802.3 |
| 최대 속도 | 1 Mbps | 10 Mbps | 20 kbps | 10 Mbps | 100 Mbps ~ 1 Gbps |
| 토폴로지 | 선형 버스 | 선형 버스 | 단일 마스터 버스 | 이중 채널 버스 | 스타/링 |
| 배선 수 | 2선 | 2선 | 1선 | 4선 | 2선(UTP) |
| 마스터 구조 | 멀티마스터 | 멀티마스터 | 단일마스터 | 멀티마스터 | 멀티마스터 |
| 실시간성 | 높음 | 중간 | 낮음 | 매우 높음 | 높음(TSN) |
| 비용 | 낮음 | 낮음 | 매우 낮음 | 높음 | 중간 |
| 주요 용도 | ECU 제어, ISOBUS | 산업 자동화 | 시트·미러·조명 | 고안전 시스템 | ADAS, 인포테인먼트 |

표의 낯선 말을 풀면 다음과 같다.
- RS-485는 공장 설비에서 널리 쓰는 직렬 통신 규격, LIN은 창문·좌석처럼 단순한 장치를 잇는 값싼 통신, FlexRay는 빠르고 안전성이 높은 제어용 통신, Automotive Ethernet은 자동차용 이더넷이다.
- 토폴로지: 장치들을 잇는 모양이다. 선형 버스는 한 줄 선로에 장치가 붙는 모양, 스타는 가운데 장치에 각 장치가 하나씩 이어지는 모양, 링은 고리 모양이다.
- 단일마스터: 마스터 하나만 먼저 말을 걸 수 있고 나머지는 대답만 한다.
- 이중 채널: 통신선을 두 벌 두어 한쪽이 고장 나도 버티게 한 구조다.
- UTP(Unshielded Twisted Pair): 금속 덮개(차폐) 없이 두 선을 꼬아 만든 케이블이다.
- 실시간성: 메시지가 정해진 시간 안에 반드시 도착한다고 보장하는 정도다. 브레이크처럼 늦으면 위험한 제어에서 중요하다. TSN(Time-Sensitive Networking)은 Ethernet에 이 보장을 더하는 추가 표준이다.
- ADAS는 차선 유지, 자동 긴급 제동 같은 운전자 보조 시스템이고, 인포테인먼트는 내비게이션, 음악 같은 정보·오락 장치다.

선택 기준을 요약하면 다음과 같다.
- <strong>단순하고 저비용</strong>: LIN (창문, 좌석 등 저속 기능)
- <strong>ECU 제어, 안정성</strong>: CAN (엔진, 브레이크, ISOBUS)
- <strong>고속 + 높은 안전성</strong>: FlexRay (전자식 파워트레인, X-by-wire)
- <strong>영상·대용량 데이터</strong>: Automotive Ethernet (카메라, 라이다)

파워트레인은 엔진에서 바퀴까지 힘을 전하는 장치(엔진, 변속기 등)이고, X-by-wire는 핸들이나 브레이크 페달과 바퀴 사이의 기계 연결을 전선과 전자 제어로 바꾼 방식이다. 라이다는 레이저로 주변 물체까지의 거리를 재는 센서다.

현재 자동차 한 대에는 CAN, LIN, Automotive Ethernet이 모두 함께 사용된다. 농기계에서는 CAN 기반의 ISOBUS가 핵심 표준이다.

::: tip 핵심 정리
- CAN은 1986년 Bosch가 개발한 2선 직렬 통신 프로토콜이고, ISO 11898로 표준화되었다. ISOBUS도 CAN 위에서 동작한다.
- 자동차, 농기계, 산업기계, 의료장비, 선박, 엘리베이터 등 폭넓게 사용된다.
- 멀티마스터: 버스가 비어 있으면 어떤 노드든 먼저 보낼 수 있다.
- 메시지 기반 브로드캐스트: 수신자 주소 대신 ID로 메시지 종류를 알리고, 필요한 노드가 골라 받는다.
- 중재: 동시에 보내면 ID 값이 낮은 메시지가 이기고, 이긴 메시지는 손상 없이 그대로 전송된다.
- 5가지 에러 검출 메커니즘으로 깨진 프레임을 찾아내 자동으로 다시 보낸다.
:::

::: details 확인 문제
1. CAN 메시지에는 받는 사람 주소가 없다. 계기판 ECU는 버스에 흐르는 수많은 메시지 가운데 자기에게 필요한 것을 어떻게 고르는가?
2. 노드 X는 ID `0x120`(=288), 노드 Y는 ID `0x110`(=272)을 동시에 보내기 시작했다. 11비트 ID를 비트 10부터 보낸다고 할 때, 어느 쪽이 이기는가? 진 쪽은 몇 번 비트에서 물러나는가?
3. 멀티마스터 방식이 마스터·슬레이브 방식과 어떻게 다른지 한 문장으로 설명하라.
4. 스터프 에러는 어떤 경우에 생기는가?
5. 자동차의 창문 모터 제어와 엔진 제어에는 각각 어떤 통신 방식이 알맞은가? 이유도 적어라.

**답 가이드**
1. 모든 노드가 버스의 메시지를 다 받은 뒤, 메시지 ID를 보고 자기에게 필요한 ID만 골라 처리한다. 나머지는 무시한다.
2. `0x120`은 2진수로 `00100100000`, `0x110`은 `00100010000`이다. 비트 10부터 비교하면 비트 8까지 같고 비트 7, 6도 같다. 비트 5에서 X는 1, Y는 0을 보낸다. 버스는 0이 되고, 1을 보낸 X가 비트 5에서 물러난다. ID 값이 작은 Y가 이긴다.
3. 마스터·슬레이브 방식은 마스터가 물어야 슬레이브가 답하지만, 멀티마스터 방식은 버스가 비어 있으면 어느 노드든 먼저 보낼 수 있다.
4. 비트 스터핑을 하는 구간에서 같은 값의 비트가 6개 이어질 때 생긴다. 보내는 쪽은 같은 값이 5개 이어지면 반드시 반대 값 비트를 넣기 때문이다.
5. 창문 모터처럼 단순하고 느려도 되는 기능은 값싼 LIN이 알맞다. 엔진처럼 여러 ECU가 실시간으로 정보를 주고받고 신뢰성이 중요한 제어는 CAN이 알맞다.
:::
