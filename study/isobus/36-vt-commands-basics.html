VT 명령어 기초

학습 목표

  • 작업기가 VT에게 보내는 명령과 VT가 작업기에게 보내는 활성화 메시지를 방향과 PGN으로 구분할 수 있다.
  • 자주 쓰는 명령(값 바꾸기, 화면 바꾸기, 숨기기·보이기)의 이름과 쓰임을 설명할 수 있다.
  • 매크로가 무엇이고 이벤트에 어떻게 묶이는지 설명할 수 있다.
  • 버튼을 누른 뒤 화면 숫자가 바뀌기까지 오가는 8바이트 프레임을 순서대로 읽을 수 있다.

시작하기 전에

  • 먼저 읽을 장: 29장 VT 기초, 32장 VT 오브젝트 풀 기초, 31장 VT 연결 관리
  • 이 장에서 처음 나오는 말
    • 명령(command): 작업기가 VT에게 "이 숫자를 바꿔라"처럼 화면을 바꾸라고 시키는 메시지
    • 활성화 메시지(activation message): VT가 작업기에게 "버튼이 눌렸다"처럼 운전자 조작을 알리는 메시지
    • 응답(response): 명령이나 활성화 메시지를 받은 쪽이 "받았다"고 돌려주는 메시지. 처리 결과가 함께 실린다
    • VT function 코드: 메시지의 첫 바이트. 이 메시지가 어떤 명령인지 가리키는 번호다
    • 매크로(Macro): 오브젝트 풀 안에 미리 넣어 둔 명령 묶음. 정해 둔 일이 생기면 VT가 스스로 실행한다
    • TAN(Transaction Number): 활성화 메시지와 그 응답을 짝짓는 4비트 일련번호

VT 화면은 작업기와 VT가 나누는 대화로 움직인다. 작업기는 VT에게 "살포량 숫자를 120으로 바꿔라"라고 명령하고, VT는 작업기에게 "운전자가 시작 버튼을 눌렀다"고 알린다. 식당에 비유하면 작업기는 메뉴판 내용을 정하는 주방이고, VT는 손님 앞에서 메뉴판을 고치고 주문을 받아 주방에 전하는 홀 직원이다. 이 장은 두 방향 대화에 쓰는 메시지를 차례로 보고, 마지막에 운전자 조작 한 번을 바이트 단위로 따라간다.

1. VT와 작업기의 두 방향 대화

이 절은 VT 메시지 전체를 두 갈래로 나누는 기준을 본다. 결론부터 말하면, 누가 먼저 말을 꺼내는지가 PGN을 정하고 첫 바이트가 무슨 말인지를 정한다.

표준은 VT를 쓰는 작업기 쪽 ECU 묶음을 Working Set이라고 부른다(29장). 이 장의 본문은 쉽게 "작업기"라고 쓰고, 표와 오브젝트 이름(Working Set 오브젝트 등)에서만 표준 이름을 쓴다.

그림 위쪽은 작업기가 먼저 말하는 경우다. 작업기가 명령을 보내면 VT가 처리한 뒤 응답한다. 그림 아래쪽은 VT가 먼저 말하는 경우다. 운전자가 버튼을 누르면 VT가 활성화 메시지로 알리고, 작업기가 응답한다.

ISO 11783-6(VT를 정하는 표준 문서)은 이 대화에 PGN(Parameter Group Number, 메시지 종류를 가리키는 번호) 두 개를 쓴다.

PGN표준 이름보내는 쪽 → 받는 쪽실리는 것
0xE600(58880)VT to ECUVT → 작업기활성화 메시지, 명령에 대한 응답
0xE700(59136)ECU to VT작업기 → VT명령, 활성화 메시지에 대한 응답

표준 이름의 ECU는 작업기를 뜻한다. 그래서 이 장의 표는 방향을 VT→ECU, ECU→VT로 적는다. E600h처럼 끝에 h를 붙인 표기도 16진수이고 0xE600과 같은 값이다.

보내는 쪽은 대부분 표와 같지만 예외가 하나 있다. 조이스틱 같은 보조 입력 장치(AUX)는 VT가 아닌데도 자기 상태 메시지를 VT to ECU PGN에 실어 모두에게 보낸다(40장). 그래서 PGN만 보고 "VT가 보냈다"고 단정하면 안 된다.

두 PGN 모두 목적지 지정(destination-specific) 형식이다. CAN ID 안에 받는 쪽 주소를 적는 형식이다(9장). 대부분의 메시지는 상대 하나에게 가고, 모두에게 알려야 하는 VT Status 같은 메시지는 받는 쪽 주소 자리에 전역 주소(0xFF, 255)를 적는다. VT의 연결·상태 관리 메시지(31장)도 같은 두 PGN을 쓴다.

두 PGN의 데이터 첫 바이트(Byte 1)는 VT function 코드다. 같은 PGN 안에서 수많은 명령을 구별하는 번호다. 예를 들어 0xA8(=168)은 Change Numeric Value(숫자 바꾸기), 0x00은 Soft Key Activation(소프트키 눌림 알림)이다. 나머지 바이트를 어떻게 읽을지는 이 코드가 정한다. 코드 전체 지도는 37장에서 본다.

명령과 활성화 메시지에는 짝이 되는 응답이 정해져 있다. 응답은 같은 VT function 코드를 쓰고 반대 방향 PGN으로 간다. 그래서 첫 바이트가 같아도 어느 PGN에 실렸는지로 명령과 응답을 구별한다. 6절 2단계에서 실제 프레임으로 확인한다.

식당 비유가 맞지 않는 곳도 하나 있다. 홀 직원(VT)은 주방이 미리 맡겨 둔 지시서(매크로, 4절)가 있으면 주방에 묻지 않고 메뉴판을 직접 고친다.

근거: ISO 11783-6 C.1, F.1, H.1, J.7.9

2. VT가 작업기에게 알리는 활성화 메시지

운전자가 화면을 만지면 VT는 그 사실을 작업기에게 알린다. 작업기는 이 알림을 받아야 살포를 시작하거나 설정값을 쓰는 실제 일을 한다. 이 절은 그런 알림의 종류와, 키를 누르고 있을 때의 규칙을 본다.

모든 VT→ECU 메시지는 목적지 지정 방식으로 전송되며, PGN 0xE600(58880)을 사용한다(1절). 반대 방향인 ECU→VT 메시지에는 별도의 PGN 0xE700(59136)이 예약되어 있다.

아래 표는 왼쪽부터 메시지 이름, PGN, 언제 나가는지, 무엇이 실리는지다. Object ID는 오브젝트 풀에서 오브젝트마다 붙인 2바이트 번호다(32장).

메시지 이름PGN트리거 조건주요 데이터
Soft Key ActivationE600h소프트키(Key 오브젝트) 누름/뗌Key Object ID, 활성화 코드 (Pressed/Released/Held)
Button ActivationE600hButton 오브젝트 누름/뗌Button Object ID, 활성화 코드
Pointing EventE600h터치스크린 탭/드래그X 좌표, Y 좌표, 터치 타입
VT Select Input ObjectE600h입력 필드 포커스 변경 (운전자 조작·ESC에 의한 것만. ECU가 Select Input Object 명령으로 요청한 변경은 통지하지 않음)Input Object ID
VT ESC MessageE600hESC 키 입력 (입력 취소)Input Object ID
VT Change Numeric ValueE600h운전자가 Input Number·Input List·Input Boolean 등에 숫자 값 입력 완료Object ID, 새 값

표에 나온 말 몇 가지를 풀어 둔다.

  • 포커스(focus): 화면에서 지금 선택되어 다음 입력을 받을 칸이다.
  • ESC: 입력을 취소하는 키다. 누르면 편집 중이던 값이 버려진다.
  • Key Group: 소프트키 여러 개를 한 묶음으로 담는 오브젝트다.
  • 사용자 레이아웃(User-Layout): 운전자가 VT 화면 한쪽에 여러 작업기의 작은 창을 골라 배치하는 기능이다(34장).

운전자가 입력 필드에 값을 넣으면 VT Change Numeric Value / VT Change String Value message가 새 값을 작업기에 전달한다. 버튼 이벤트와 함께 사용자 입력이 작업기에 도달하는 핵심 경로다. 입력 오브젝트가 변수(Variable)를 참조하면 메시지에는 입력 오브젝트가 아니라 변수 오브젝트의 Object ID가 실린다. 변수는 여러 칸이 함께 읽는 값 저장소 오브젝트다.

화면이 지금 어느 마스크를 보여 주는지 알고 싶다면 VT Change Active Mask를 보면 안 된다. 이름과 달리 이 메시지는 오류 통지용이다. 대신 VT Status message를 참조해야 한다. 이 메시지는 활성 Working Set과 표시 중인 마스크 ID를 담아 초당 1회 모든 장치에 보낸다(31장).

활성화 코드: 누름, 뗌, 누르고 있음

Soft Key Activation과 Button Activation에는 키가 어떤 상태인지 알리는 활성화 코드가 1바이트 실린다. 값은 다음과 같다.

코드의미
0Released (눌렀다 뗌)
1Pressed (누름)
2Held (길게 누르는 중, 반복 전송)
3Aborted (누르다 취소)

코드 1과 0은 상태가 바뀐 순간에 한 번씩 나간다. 운전자가 키를 계속 누르고 있으면 코드 2 메시지가 200 ms마다 반복 전송된다. 작업기는 메시지 간격이 300 ms를 넘으면 키가 릴리스된 것으로 처리해야 한다. 뗌 메시지를 놓쳐도 키가 계속 눌린 것으로 남지 않게 하는 안전장치로 볼 수 있다.

코드 3(Aborted)은 VT 버전 4부터 있다. 터치 화면에서 버튼을 누른 채 손가락을 버튼 밖으로 밀어낸 경우처럼, 누름을 취소할 수단이 있는 VT는 코드 0 대신 코드 3을 보낸다. 그래서 작업기는 "눌렀다 뗌"과 "누르다 취소"를 구별할 수 있다.

메시지에는 Object ID·활성화 코드 외에 Parent Object ID(표시 중인 마스크 또는 Key Group)와 key code(소프트키 코드 0은 알람 ACK 전용)도 실린다. key code는 작업기가 키마다 정해 둔 번호이고, 알람 ACK는 운전자가 경보 화면을 확인했다는 표시다(39장). 바이트 배치는 6절 1단계에서 실제 프레임으로 본다.

응답 규칙과 TAN

작업기는 활성화 메시지를 받으면 같은 내용을 되돌려 보내는 응답을 보낸다. 받은 값을 그대로 되돌려 싣는 것을 반향(echo)이라고 한다.

응답이 꼭 필요한지는 VT 버전에 따라 다르다. VT 버전은 VT와 작업기가 표준의 어느 판 규칙을 따르는지 나타내는 번호다(29장). 아래의 "조합"은 VT와 작업기가 함께 따르는 버전을 말한다.

  • v5 이하 조합에서는 응답이 선택이다.
  • v6 이상 조합에서는 200 ms 이내 응답이 필수다.
  • 300 ms 안에 응답이 없으면 VT는 최대 3회 재시도한다.
  • 그래도 응답이 없으면 VT는 그 작업기가 예기치 않게 꺼진 것(unexpected shutdown)으로 취급한다.

버튼을 빠르게 연타하면 메시지와 응답이 겹쳐 오갈 수 있다. 어느 응답이 어느 메시지의 것인지 가리려고, v6부터는 메시지에 실리는 4비트 TAN(Transaction Number)으로 메시지-응답 쌍을 짝맞춘다. 식당의 주문 번호와 같다. 주방이 "3번 주문 받았다"고 답하면 홀 직원은 어느 주문에 대한 답인지 헷갈리지 않는다.

TAN은 4비트라 0~15 가운데 하나다. VT는 새 메시지를 보낼 때마다 TAN을 바꾸고(예: 1씩 늘림), 작업기는 응답에 받은 TAN을 그대로 싣는다. 같은 메시지를 재시도할 때는 TAN을 바꾸지 않는다.

근거: ISO 11783-6 4.6.18, G.2, H.1, H.2, H.8, H.12

3. 작업기가 VT에게 보내는 명령

작업기는 센서 값이 바뀌면 화면 숫자를 고치고, 상황이 바뀌면 다른 화면을 띄운다. 이 절은 그때 쓰는 명령을 쓰임별로 묶어 보고, 명령 하나를 바이트로 읽어 본다.

작업기→VT 명령은 PGN 0xE700(59136) 목적지 지정 메시지로 전송된다. 모든 명령에는 오류 코드(에러 코드)를 담은 응답(response)이 정의되어 있다. 오류 코드는 VT가 명령을 처리하다 문제가 생기면 응답에 넣는 값이고, 0이면 성공이다. 송신자는 응답을 받은 뒤 다음 명령을 보내는 것이 원칙이다. 단, 1.5초 안에 응답이 없으면 다음 명령을 보낼 수 있다. 응답과 오류 코드를 읽는 법은 37장에서 자세히 본다.

아래 표들에서 명령 이름 뒤 괄호 속 A8h 같은 값은 그 명령의 VT function 코드다.

값 갱신 명령어

Output Number는 숫자를 보여 주기만 하는 칸, Input Number는 운전자가 숫자를 넣는 칸이다. 오브젝트 종류는 33장에서 자세히 다룬다.

명령어 이름대상 오브젝트설명
Change Numeric Value (A8h)Output Number, Input Number, 변수 등숫자 값을 새 값으로 갱신
Change String Value (B3h)Output String, Input String문자열 값을 새 값으로 갱신
Change List Item (B1h)Input List, Output List목록의 특정 항목을 변경

화면 전환 명령어

Data Mask는 작업 화면 한 장, Alarm Mask는 경보 화면, Soft Key Mask는 화면 옆에 늘어선 소프트키 묶음이다(32장). Active Mask는 그 작업기가 VT 화면을 차지했을 때 보이는 마스크다.

명령어 이름설명
Change Active Mask (ADh)Working Set의 활성 Data Mask 또는 Alarm Mask를 교체
Change Soft Key Mask (AEh)Data Mask에 연결된 Soft Key Mask를 교체

속성 변경 명령어

AID(Attribute ID)는 오브젝트의 속성(배경색, 폭 등)마다 붙은 번호다(33장). 부모 오브젝트는 그 오브젝트를 담고 있는 마스크나 Container다.

명령어 이름설명
Change Attribute (AFh)AID(Attribute ID)가 부여된 속성(배경색, 폭·높이 등)을 런타임에 변경. 위치는 Change Child Location/Position, 문자열은 Change String Value를 사용
Change Priority (B0h)Alarm Mask의 우선순위를 변경
Change Size (A6h)오브젝트의 너비/높이를 변경
Change Child Location (A5h)부모 오브젝트 내 자식 오브젝트의 위치를 상대 이동
Change Child Position (B4h)부모 오브젝트 좌상단 기준 절대 좌표로 자식 오브젝트의 위치를 변경 (Parent Object ID 함께 지정)

상대 이동은 "지금 자리에서 오른쪽으로 10픽셀"처럼 옮기는 것이고, 절대 좌표는 "부모 왼쪽 위에서 (200, 30) 자리"처럼 위치를 바로 정하는 것이다.

표시 제어 명령어

Container는 여러 오브젝트를 한 묶음으로 담는 오브젝트다. 숨기고 싶은 오브젝트를 Container에 넣어 두면 Container째로 숨기거나 보일 수 있다.

명령어 이름설명
Hide/Show Object (A0h)Container 오브젝트의 표시/숨김 제어. 개별 오브젝트를 숨기려면 Container로 묶어야 한다
Enable/Disable Object (A1h)입력 오브젝트의 활성화/비활성화

명령 하나를 바이트로 읽기: Change Numeric Value

CAN 데이터 프레임 하나는 데이터를 최대 8바이트 싣는다(4장). 아래 그림은 Change Numeric Value 명령의 8바이트 배치다. 이 블로그의 바이트 표와 그림은 다음 규칙으로 읽는다.

  • 바이트 번호는 1부터 센다. Byte 1이 맨 먼저 나가는 바이트다.
  • 2바이트 이상인 값은 리틀 엔디언(little endian, LE)이다. 낮은 자리 바이트가 먼저 온다. 그래서 Object ID 0x000B(11)는 0B 00 순서로 실린다.
  • 예약(reserved) 자리는 나중에 기능을 넣으려고 비워 둔 바이트다. 보내는 쪽은 이 자리를 FF로 채운다.

그림의 Command Byte가 VT function 코드다.

예를 들어 살포량을 보여 주는 Output Number 0x000B를 120으로 바꾸는 명령은 A8 0B 00 FF 78 00 00 00이다. 한 바이트씩 읽으면 다음과 같다.

  1. Byte 1 A8: VT function 코드다. Change Numeric Value를 뜻한다.
  2. Byte 2~3 0B 00: 리틀 엔디언이므로 뒤집어 읽는다. 0x000B, 곧 11번 오브젝트다.
  3. Byte 4 FF: 예약 자리다.
  4. Byte 5~8 78 00 00 00: 뒤집으면 0x00000078이고, 10진수로 120이다.

Byte 5~8의 값 크기는 대상 오브젝트 타입에 따라 다르다. Input Boolean은 1바이트, Meter·Bar Graph류는 2바이트, Input/Output Number·Number Variable은 4바이트이며 미사용 바이트는 0으로 채운다. 위 예시는 4바이트(32bit) 오브젝트 기준이다.

VT는 같은 첫 바이트 A8로 응답하고, 명령의 Byte 4(예약) 자리에 오류 코드를 넣어 돌려준다. 6절 4단계에서 실제 응답을 본다.

근거: ISO 11783-6 F.1, F.22, F.23

4. 매크로: VT가 스스로 실행하는 명령 묶음

버튼 하나 누를 때마다 VT가 작업기에게 묻고 답을 기다리면 버스도 바쁘고 화면 반응도 늦다. 매크로는 간단한 화면 동작을 VT에게 미리 맡겨 두는 방법이다. 식당으로 치면 주방이 홀 직원에게 "손님이 디저트 메뉴판을 달라고 하면 그냥 갖다 줘"라는 지시서를 미리 맡겨 두는 것과 같다.

매크로(Macro)는 오브젝트 풀에 미리 넣어 둔 이벤트 기반 자동 동작 목록이다. 이벤트(event)는 "오브젝트가 화면에 나타났다", "키가 눌렸다"처럼 VT 안에서 생기는 일이다. 특정 이벤트가 발생하면 VT가 자동으로 매크로를 실행한다.

매크로를 쓰면 좋은 점은 세 가지다.

  • 작업기에 메시지를 보내지 않고도 VT 안에서 화면 변화를 처리하므로 작업기 부하가 준다.
  • 작업기의 답을 기다리지 않으니 반응 속도가 빨라진다.
  • 매크로 안에서 실행된 명령에 대해서는 VT가 CAN 버스에 응답(response)을 보내지 않으므로 버스 트래픽도 줄어든다.

매크로에 담는 것은 VT가 실행하는 명령뿐이다. 살포 시작처럼 작업기 기계가 직접 할 일은 매크로로 대신할 수 없다.

이벤트 종류

아래 표는 매크로를 걸 수 있는 대표 이벤트다. 왼쪽이 이벤트 이름, 오른쪽이 일어나는 때다. 매크로의 바이트 인코딩과 실행 규칙은 38장에서 자세히 본다.

이벤트 이름발생 조건
On Show오브젝트가 화면에 표시될 때
On Hide오브젝트가 화면에서 숨겨질 때
On Enable입력 오브젝트가 활성화될 때
On Disable입력 오브젝트가 비활성화될 때
On Change Active Mask활성 마스크가 변경될 때
On Change Soft Key MaskSoft Key Mask가 변경될 때
On Key PressKey 또는 Button이 눌릴 때
On Key ReleaseKey 또는 Button이 해제될 때
On Change Attribute오브젝트 속성이 변경될 때
On Change ValueChange Numeric/String Value 명령으로 값이 변경될 때
On Input Field Selection입력 필드가 선택될 때
On ESCESC 이벤트 발생 시
On Activate / On DeactivateWorking Set이 활성/비활성이 될 때

마지막 줄의 활성은 그 작업기의 화면이 VT 주 화면을 차지한 상태이고, 비활성은 다른 작업기에게 주 화면을 넘긴 상태다.

예: 버튼에 매크로 걸기

아래는 "설정 화면" 버튼을 누를 때 Active Mask를 ID 2(설정 화면)로 변경하는 매크로이다. 오브젝트 풀을 사람이 읽기 쉬운 XML로 적었다. 실제로 VT에 올라가는 것은 이 내용을 바이트로 바꾼 풀이다(32장).

<!-- 매크로 정의: Active Mask를 ID 2로 변경 -->
<macro id="50">
  <change_active_mask working_set_id="0" new_active_mask="2" />
</macro>

<!-- Button에 이벤트 바인딩 -->
<button id="20"
        width="100" height="40"
        background_colour="7"
        border_colour="8"
        key_code="1">
  <macro_ref event_id="24" macro_id="50" />
  <!-- event_id 24 = On Key Press -->
  <outputstring id="21" ... value="설정" />
</button>

<macro id="50">가 매크로 오브젝트 50번이고, 안에 Change Active Mask 명령 하나가 들어 있다. Button 20 안의 <macro_ref event_id="24" macro_id="50" />는 "On Key Press 이벤트(번호 24)가 나면 매크로 50을 실행하라"는 연결이다. 운전자가 이 버튼을 누르면 VT는 작업기에게 묻지 않고 바로 설정 화면(마스크 2)을 띄운다. 버튼이 눌렸다는 활성화 메시지(Button Activation)는 이때도 작업기에 그대로 간다. 매크로는 그 알림을 대신하지 않고 화면 쪽 처리만 앞당긴다.

매크로 내에서는 여러 명령을 순차적으로 나열할 수 있다.

<macro id="51">
  <!-- 순차 실행: 경고 컨테이너 표시 후 Output String 21의 배경색(AID 3)을 빨강(12)으로 변경 -->
  <show_hide_object object_id="60" value="show" />
  <change_attribute object_id="21"
                    attribute_id="3"
                    value="12" />
</macro>

명령은 위에서부터 차례로 실행된다. 먼저 Container 60(경고 묶음)이 보이고, 이어서 Output String 21의 배경색이 빨강(색 번호 12)으로 바뀐다.

근거: ISO 11783-6 4.6.18, 4.6.22, B.16

5. 버튼 하나가 화면 숫자를 바꾸기까지

지금까지 본 메시지와 명령을 하나의 흐름으로 이어 본다. 이 절은 시간 순서 그림 두 개로 큰 흐름을 잡고, 6절에서 같은 흐름을 바이트로 따라간다.

그림 읽는 법은 다음과 같다.

  • 세로선 하나가 참가자 하나다(운전자, VT, 작업기 ECU).
  • 위에서 아래로 시간이 흐르고, 가로 화살표 하나가 메시지 하나다.
  • 실선은 요청이나 통지, 점선은 응답이다. 참가자 세로선 위의 상자는 그 참가자 안에서 일어나는 처리다.
  • 화살표 아래 작은 글씨는 메시지에 실린 주요 값이다.

예 1: "시작" 버튼으로 살포를 시작하고 살포량 표시하기

운전자가 VT의 "시작" 버튼을 눌렀을 때, 살포 시스템이 시작되고 화면의 상태값이 갱신되는 전체 흐름이다. 이 예의 "시작" 버튼(Object ID 20)은 4절 XML의 "설정" 버튼과 번호만 같은 별개의 예시다.

단계별로 읽으면 다음과 같다.

  1. 운전자가 "시작" 버튼(Button 오브젝트 0x0014, 20)을 터치한다.
  2. VT가 Button Activation(활성화 코드 1, Pressed)을 PGN E600h로 보낸다.
  3. 작업기 ECU가 살포 시스템을 시작하고, Button Activation 응답을 PGN E700h로 보낸다. 이 응답은 v5 이하에서는 선택이고 v6 이상에서는 200 ms 이내에 보내야 한다.
  4. 운전자가 손을 떼면 VT가 Button Activation(활성화 코드 0, Released)을 보내고, 작업기가 다시 응답한다.
  5. 작업기는 살포량 센서 값(예: 120 kg/h)을 읽어 Change Numeric Value로 Output Number 0x000B에 120을 보낸다.
  6. VT가 화면에 "살포량: 120 kg/h"를 표시한다. 그 뒤로는 작업기가 새 센서 값을 읽을 때마다 같은 명령으로 화면을 갱신한다.

그림은 흐름을 보이려고 Change Numeric Value의 응답 화살표를 생략했다. 실제로는 이 명령에도 VT의 응답이 따른다. 그림의 "100 ms 주기 갱신"도 예시일 뿐이다. 값이 바뀌지 않았으면 보내지 않는 편이 권고에 맞다(37장).

예 2: 경고가 나면 Alarm Mask로 바꾸기

작업기가 이상을 감지하면 경보 화면(Alarm Mask)을 띄우고, 운전자가 확인하면 원래 작업 화면으로 돌아온다.

  1. 작업기 ECU가 온도 임계값 초과(92°C > 90°C)를 감지한다.
  2. 작업기가 Change Active Mask로 Active Mask를 Alarm Mask(0x0003, 3)로 바꾼다.
  3. VT가 경고 화면("온도 과열 경고!")을 띄운다. Alarm Mask는 현재 Data Mask 위에 우선순위로 표시된다.
  4. 운전자가 "확인" 소프트키를 누르면 VT가 Soft Key Activation을 보낸다.
  5. 작업기가 다시 Change Active Mask로 원래 Data Mask(ID 1)를 띄워 일반 작업 화면이 돌아온다.

이 그림도 흐름을 보이려고 응답 화살표를 생략했다. 실제로는 명령과 활성화 메시지마다 응답이 따른다. 경보 화면을 내리는 것은 운전자의 확인 키 자체가 아니라 작업기가 보내는 Change Active Mask라는 점을 눈여겨 둔다. 경보의 우선순위와 소리 규칙은 39장에서 본다.

정리하면, 버튼 클릭 → Button Activation → 작업기 처리 → Change Numeric Value → 화면 갱신이 기본 상호작용 패턴이다.

근거: ISO 11783-6 4.6.10.1, F.22, F.34, H.1, H.4

6. 운전자 조작 따라가기: 프레임 14개를 바이트로

앞 절의 그림이 큰 흐름이었다면, 여기서는 운전자가 화면을 실제로 조작할 때 오가는 메시지를 시간순으로 8바이트까지 끝까지 따라간다. 시나리오는 4단계로 이루어진다.

  1. 운전자가 소프트키를 누른다
  2. 그 소프트키에 연결된 동작으로 작업기가 화면을 전환한다
  3. 운전자가 입력 필드에 숫자를 입력한다
  4. 작업기가 표시값을 갱신한다

Object ID는 4절의 매크로 예시(working_set_id="0", new_active_mask="2")와 5절의 그림(Output Number ID 0x000B, "살포량" 표시값)에서 쓴 값을 그대로 이어받는다. 운전자가 소프트키로 설정 화면을 연 뒤, 입력 필드에 살포량 목표치 150을 입력해 확정하면 작업기가 같은 Output Number(0x000B)를 150으로 갱신하는 흐름이다. VT와 작업기는 모두 v6 이상이라고 가정한다. 그래서 활성화 메시지마다 TAN이 실린다.

단계마다 나오는 프레임 표는 이렇게 읽는다.

  • 한 줄이 CAN 프레임 하나다.
  • 시각은 첫 프레임부터 잰 경과 시간이다. 설명용으로 정한 값이다.
  • 방향은 1절의 PGN 이름을 따른다. VT→ECU는 E600h, ECU→VT는 E700h다.
  • 8바이트 hex는 Byte 1부터 Byte 8까지 왼쪽에서 오른쪽 순서다. 3절의 바이트 읽는 규칙(1부터 세기, 리틀 엔디언, 예약 FF)이 그대로 적용된다.

1단계: 운전자가 소프트키를 누른다

오가는 메시지: VT가 Soft Key Activation으로 "눌렀다"와 "뗐다"를 차례로 알리고, 작업기가 그때마다 같은 8바이트로 응답한다.

소프트키 Object ID는 0x0032(50), 부모는 현재 표시 중인 Data Mask 0x0001(1), 소프트키 코드는 5다. v6 이상이므로 Byte 8의 상위 니블에 TAN이 실린다. 니블(nibble)은 4비트, 곧 16진수 한 자리다. Soft Key Activation의 바이트 배치는 다음과 같다.

2단계: 작업기가 화면을 전환한다

오가는 메시지: 작업기가 Change Active Mask 명령으로 "설정 화면을 띄워라"라고 보내고, VT가 오류 없음으로 응답한다.

작업기는 소프트키 뗌 메시지에 응답한 뒤, 이 소프트키에 매크로가 아니라 작업기 프로그램으로 직접 연결해 둔 동작을 실행한다고 가정한다. 그 동작은 Working Set 0x0000의 Active Mask를 설정 화면(0x0002)으로 바꾸는 것이다. 0x0000은 작업기 풀의 맨 위 오브젝트인 Working Set 오브젝트의 ID다.

Change Active Mask 명령은 Byte 2~3에 Working Set 오브젝트 ID, Byte 4~5에 새 Active Mask ID를 싣고 Byte 6~8은 예약(FF)이다. 응답은 Byte 2~3에 새 Active Mask ID, Byte 4에 오류 코드를 싣고 Byte 5~8은 예약이다.

시각방향PGN8바이트 hex의미
t=190 msECU→VTE700hAD 00 00 02 00 FF FF FFChange Active Mask 명령, WS ID=0x0000, 새 Active Mask=0x0002
t=195 msVT→ECUE600hAD 02 00 00 FF FF FF FF응답: 새 Active Mask 반향(Byte 2,3), Error Code=0(Byte 4)

여기서 방향이 뒤집힌다는 점이 핵심이다. 1단계는 VT가 먼저 보내는 활성화 메시지(message)라 E600h를 쓰지만, 2단계는 작업기가 먼저 보내는 명령(command)이라 E700h를 쓴다. 같은 function code(0xAD, 173)가 명령(E700h)과 응답(E600h)에 함께 쓰이므로, 명령인지 응답인지는 어느 PGN(방향)에 실렸는지로 갈린다. PGN은 메시지 종류가 아니라 방향(VT→ECU, ECU→VT)에 따라 정해진다.

3단계: 운전자가 입력 필드에 숫자를 입력한다

오가는 메시지: VT가 VT Select Input Object로 "입력 칸이 편집용으로 열렸다", VT Change Numeric Value로 "새 값은 150이다", 다시 VT Select Input Object로 "입력 칸이 닫혔다"를 알리고, 작업기가 하나하나 응답한다.

설정 화면의 Input Number 오브젝트(0x0028, 40)를 운전자가 탭해 포커스·편집을 열고, 150을 입력해 확정한 뒤 다른 곳으로 포커스를 옮겨 닫는다. 두 메시지의 바이트 배치는 다음과 같다. TAN이 실리는 바이트가 메시지마다 다르다는 점에 주의한다.

150을 16진수로 쓰면 0x96이다. 4바이트 리틀 엔디언이라 96 00 00 00으로 실린다. VT Change Numeric Value의 Byte 4 4F는 위 4비트 TAN 4와 아래 4비트 예약 F를 합친 값이다.

VT Change Numeric Value는 "값이 실제로 바뀌었는지와 무관하게" 확정 시점에 전송된다. 입력을 취소했다면 이 메시지 대신 VT ESC message(VT function 코드 04)가 나갔을 것이다. VT Select Input Object가 열림과 닫힘으로 두 번 나오는 이유는, 이 메시지가 포커스를 얻을 때와 잃을 때(편집용으로 열고 닫을 때 포함) 각각 나가기 때문이다. 운전자가 값을 입력하는 동안(닫히기 전)에는 편집이 끝나지 않은 상태다.

4단계: 작업기가 표시값을 갱신한다

오가는 메시지: 작업기가 Change Numeric Value 명령으로 화면의 살포량 칸(0x000B)을 150으로 바꾸고, VT가 오류 없음으로 응답한다.

작업기는 입력이 확정된 것을 확인한 뒤(선택 해제 메시지에 응답한 뒤), 5절에서 다루었던 Output Number 0x000B를 새 값 150으로 갱신한다.

시각방향PGN8바이트 hex의미
t=8520 msECU→VTE700hA8 0B 00 FF 96 00 00 00Change Numeric Value 명령, Object ID=0x000B, Byte4 Reserved=FF, 값=150
t=8525 msVT→ECUE600hA8 0B 00 00 96 00 00 00응답: Error Code=0(Byte 4), 값 반향

3절에서 읽은 바이트 배치 그대로다. 응답은 명령의 Byte 4(예약 FF) 자리에 오류 코드 00을 넣고 나머지 값은 그대로 돌려준다.

이 흐름에서 확인되는 규칙

  • 방향이 PGN을 정한다: 1·3단계(VT가 먼저 보냄)는 항상 E600h, 2·4단계(작업기가 먼저 보냄)는 항상 E700h다. Soft Key Activation(0x00), VT Select Input Object(0x03), VT Change Numeric Value(0x05)는 VT가 먼저 보내는 활성화 메시지이고, Change Active Mask(0xAD), Change Numeric Value(0xA8)는 작업기가 먼저 보내는 명령이다. 같은 "보내고 응답받는" 짝이라도 어느 쪽이 먼저 보내는 메시지인지에 따라 발신 방향과 PGN이 고정된다.
  • 명령-응답 규칙: 표의 모든 프레임에 응답이 따라붙고, 다음 프레임은 그 응답 이후에만 나간다. 작업기 명령(2·4단계)은 1.5 s 안에 응답이 없으면 다음 명령을 보낼 수 있다. 활성화 메시지(1·3단계, v6 이상)는 200 ms 이내 응답이 필수이며 300 ms 안에 안 오면 최대 3회 재시도한다.
  • TAN은 활성화 메시지에만 실린다. Soft Key Activation은 Byte 8의 상위 니블, VT Select Input Object도 Byte 8의 상위 니블, VT Change Numeric Value는 Byte 4의 상위 니블이다. 작업기 명령과 그 응답(2·4단계)에는 TAN이 없다. 이 쌍은 애초에 겹쳐 발생할 일이 드물고 순차적으로 처리되기 때문이다.
  • 홀드·릴리스: 1단계처럼 누름-뗌 간격이 200 ms 미만이면 "Still held(code 2)" 프레임 없이 곧바로 릴리스로 끝난다. 반대로 200 ms를 넘겨 누르고 있으면 그 사이 code=2 프레임이 200 ms 간격으로 반복되고, 작업기는 이 반복이 300 ms 넘게 끊기면 릴리스로 간주해야 한다.
원문을 가진 독자를 위한 메모

TAN을 싣는 바이트의 하위 4비트는 Soft Key Activation(H.2)뿐 아니라 VT Select Input Object(H.8)·VT Change Numeric Value(H.12)에서도 원문이 "Bits 3~0 Reserved, set to F16"으로 규정한다. 위 표의 Fh는 이 규정을 따른 값이다. Change Active Mask 명령·응답의 꼬리 바이트도 F.34(Byte 6~8)·F.35(Byte 5~8)에 Reserved FF16으로 명시되어 있다. 두 PGN이 메시지 묶음(부록)이 아니라 방향에 배정된다는 점은 C.1과 Table A.5에서 확인할 수 있다.

아래 코드는 위 표의 프레임 14개를 파이썬으로 다시 조립해, 모두 8바이트인지와 대표 프레임 값이 표와 같은지 확인한다. tan_byte()는 TAN을 위 4비트에, F를 아래 4비트에 넣고, le()는 값을 리틀 엔디언 바이트 목록으로 바꾼다. 주석 괄호 속의 영문자·숫자 번호는 표준 문서의 절 번호라서 몰라도 코드를 읽는 데 지장이 없다.

파이썬으로 14개 프레임 검산해 보기
def tan_byte(tan, low_nibble=0xF):
    return ((tan & 0xF) << 4) | (low_nibble & 0xF)

def le(value, nbytes):
    return [(value >> (8 * i)) & 0xFF for i in range(nbytes)]

def hx(bs):
    return " ".join(f"{b:02X}" for b in bs)


# 1) Soft Key Activation (H.2~H.3, VT function=0)
key_obj, parent_mask, key_code = 0x0032, 0x0001, 0x05

press = [0x00, 0x01] + le(key_obj, 2) + le(parent_mask, 2) + [key_code, tan_byte(1)]
release = [0x00, 0x00] + le(key_obj, 2) + le(parent_mask, 2) + [key_code, tan_byte(2)]

# 2) Change Active Mask (F.34~F.35, VT function=173=0xAD)
ws_obj, new_mask = 0x0000, 0x0002
cam_cmd = [0xAD] + le(ws_obj, 2) + le(new_mask, 2) + [0xFF, 0xFF, 0xFF]
cam_resp = [0xAD] + le(new_mask, 2) + [0x00] + [0xFF, 0xFF, 0xFF, 0xFF]

# 3) VT Select Input Object (H.8~H.9, function=3) + VT Change Numeric Value (H.12~H.13, function=5)
input_obj, new_val = 0x0028, 150
sel_open = [0x03] + le(input_obj, 2) + [0x01, 0x01, 0xFF, 0xFF, tan_byte(3)]
cnv_msg = [0x05] + le(input_obj, 2) + [tan_byte(4)] + le(new_val, 4)
sel_close = [0x03] + le(input_obj, 2) + [0x00, 0x00, 0xFF, 0xFF, tan_byte(5)]

# 4) Change Numeric Value command (F.22~F.23, VT function=168=0xA8)
disp_obj = 0x000B
cnv_cmd = [0xA8] + le(disp_obj, 2) + [0xFF] + le(new_val, 4)
cnv_cmd_resp = [0xA8] + le(disp_obj, 2) + [0x00] + le(new_val, 4)

frames = [press, press, release, release, cam_cmd, cam_resp,
          sel_open, sel_open, cnv_msg, cnv_msg, sel_close, sel_close,
          cnv_cmd, cnv_cmd_resp]

for f in frames:
    assert len(f) == 8
print(hx(press))      # 00 01 32 00 01 00 05 1F
print(hx(cam_cmd))    # AD 00 00 02 00 FF FF FF
print(hx(cnv_msg))    # 05 28 00 4F 96 00 00 00
print(hx(cnv_cmd))    # A8 0B 00 FF 96 00 00 00
print("14 frames, all 8 bytes: OK")

실행하면 대표 프레임 네 줄(각 줄 끝 주석과 같은 값)과 14 frames, all 8 bytes: OK가 출력된다. 응답 프레임은 받은 메시지를 그대로 반향하므로 frames 목록에 같은 변수를 두 번 넣었다.

근거: ISO 11783-6 C.1, F.22, F.23, F.34, F.35, H.1~H.3, H.8, H.9, H.12, H.13

핵심 정리

  • VT와 작업기는 두 PGN으로 대화한다. VT가 먼저 보내는 활성화 메시지는 0xE600(VT to ECU), 작업기가 먼저 보내는 명령은 0xE700(ECU to VT)을 쓰고, 응답은 반대 방향 PGN으로 간다. 모두 목적지 지정 방식이다.
  • 첫 바이트(VT function 코드)가 메시지 종류를 정한다. 명령과 그 응답은 같은 코드를 쓰므로 PGN과 첫 바이트를 함께 봐야 한다.
  • 활성화 메시지는 버튼·소프트키·터치·ESC 같은 운전자 조작과 입력값(VT Change Numeric/String Value)을 작업기에 전한다. v6 이상에서는 200 ms 안에 응답해야 하고, TAN으로 메시지와 응답을 짝짓는다.
  • 명령은 화면 값 갱신(Change Numeric/String Value), 화면 전환(Change Active Mask), 속성 변경에 쓰며, 응답을 받은 뒤 다음 명령을 보낸다(1.5초 타임아웃).
  • 매크로는 오브젝트 풀에 미리 넣어 둔 이벤트 기반 자동 동작으로, 작업기 개입 없이 VT가 실행한다.
  • 버튼 클릭 → Button Activation → 작업기 처리 → Change Numeric Value → 화면 갱신이 기본 상호작용 패턴이다.
확인 문제
  1. 운전자가 화면의 버튼을 눌렀다. VT가 작업기에게 보내는 알림은 어느 PGN을 쓰는가? 작업기가 그 알림에 응답할 때는 어느 PGN을 쓰는가?
  2. 첫 바이트가 AD인 프레임 두 개가 있다. 하나는 PGN 0xE700, 다른 하나는 PGN 0xE600에 실렸다. 각각 무엇인가?
  3. Output Number 0x000B를 120으로 바꾸는 Change Numeric Value 명령의 8바이트를 써 보라.
  4. 매크로를 쓰면 무엇이 좋아지는가? 두 가지 이상 들라.
  5. VT 버전 6 환경에서 운전자가 소프트키를 0.5초 동안 누르고 있다가 뗐다. VT가 보내는 Soft Key Activation을 활성화 코드 순서대로 적고, TAN이 어떻게 바뀌는지 말하라.

답 가이드

  1. 버튼 알림(Button Activation)은 VT가 먼저 보내므로 0xE600(VT to ECU)을 쓴다. 작업기의 응답은 반대 방향인 0xE700(ECU to VT)으로 간다.
  2. 0xE700에 실린 것은 작업기가 보낸 Change Active Mask 명령이고, 0xE600에 실린 것은 VT가 돌려준 그 응답이다. 첫 바이트만으로는 둘을 구별할 수 없다.
  3. A8 0B 00 FF 78 00 00 00이다. Byte 1 A8은 Change Numeric Value, Byte 2~3 0B 00은 리틀 엔디언으로 쓴 Object ID 0x000B, Byte 4 FF는 예약, Byte 5~8 78 00 00 00은 120(0x78)을 4바이트 리틀 엔디언으로 쓴 값이다.
  4. 작업기에 묻고 답을 기다리지 않으니 화면 반응이 빨라지고 작업기 부하가 준다. 매크로 안에서 실행된 명령에는 VT가 응답을 보내지 않으니 버스 트래픽도 준다.
  5. 누르는 순간 코드 1(Pressed), 누르고 있는 동안 200 ms마다 코드 2(Held)가 나가므로 약 200 ms와 400 ms 무렵에 코드 2가 두 번, 뗄 때 코드 0(Released)이 나간다. 메시지마다 새 상태나 새 반복이므로 TAN이 하나씩 바뀐다. 응답이 없어 같은 메시지를 재시도할 때만 TAN을 그대로 둔다.
