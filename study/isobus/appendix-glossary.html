용어 사전

본문에서 점선 밑줄이 그어진 낱말을 누르면 그 자리에 짧은 풀이가 뜬다. 이 페이지는 그 풀이를 분야별로 모두 모은 전체 목록이다. 항목마다 영문 이름과 한글 이름, 쉬운 풀이, 더 알아 둘 내용을 적었고, 그 용어를 가장 자세히 다루는 장으로 가는 링크를 붙였다.

통신 기초

16진수 hexadecimal
0~9와 A~F, 16개 기호로 수를 적는 방법이다. 한 자리가 4비트라서 1바이트를 두 자리(00~FF)로 적는다. 앞에 0x를 붙여 0xEA00처럼 쓴다.
예를 들어 0xEA00은 10진수로 59904다. CAN 로그와 표준 문서는 대부분 16진수로 값을 적는다.
1장에서 자세히
2진수 binary
0과 1 두 숫자만 쓰는 수 표기다. 자리가 하나 올라갈 때마다 자릿값이 2배가 된다. 비트를 늘어놓은 것이 곧 2진수다.
예를 들어 2진수 1010은 10진수로 10이고, 4자리씩 끊으면 16진수 한 자리가 된다.
1장에서 자세히
ASCII American Standard Code for Information Interchange
영문자, 숫자, 기호에 0~127 번호를 붙인 문자 코드다. 예를 들어 0x41이 A다. 문자열은 수치 값과 달리 왼쪽 글자부터 차례로 보낸다.
BOM Byte Order Mark
문자열 맨 앞에 붙여 바이트 순서를 알리는 표시다. ISOBUS의 WideString은 FEFF를 리틀 엔디언으로 적은 FF FE로 늘 시작한다.
이 2바이트는 문자열 길이에는 들어가지만 글자 수에는 들어가지 않는다.
35장에서 자세히
code plane과 surrogate pair
Unicode 문자 번호를 65536개씩 묶은 단위가 code plane이다. 0번 plane 밖의 문자는 UTF-16에서 16비트 값 두 개, 곧 surrogate pair로 적는다.
Unicode는 0~16번, 17개의 code plane으로 문자를 정리한다. ISOBUS의 WideString에서는 surrogate pair가 WideChar 두 개를 차지한다.
18장에서 자세히
ECU Electronic Control Unit · 전자 제어 장치
센서 값을 읽고 모터나 밸브를 제어하는 작은 컴퓨터 장치다. 물리적으로 독립된 장치 하나를 뜻하며, ISOBUS에서는 ECU 하나가 CF(제어 기능)를 여러 개 담을 수 있다.
18장에서 자세히
float32 IEEE 754 single precision · 32비트 부동소수점
실수를 32비트로 근사해 담는 형식(IEEE 754 단정밀도)이다. 0.1 같은 값은 정확히 담기지 않아 계산 결과에 아주 작은 오차가 생길 수 있다.
49장에서 자세히
ID(식별자) identifier
CAN 프레임 앞부분의 번호로, 이 프레임이 무슨 내용인지와 우선순위를 알려 준다. 값이 작을수록 우선순위가 높다.
고전 CAN의 ID는 11비트 또는 29비트이고, J1939와 ISOBUS는 29비트 ID를 우선순위, PGN, 보낸 이 주소로 나눠 쓴다.
4장에서 자세히
ISO International Organization for Standardization · 국제표준화기구
나라마다 다른 규격을 국제 표준으로 맞추는 기구다. ISO 11898(CAN), ISO 11783(ISOBUS)처럼 번호로 표준 문서를 부른다.
18장에서 자세히
ISO/IEC 8859
문자 하나를 1바이트로 적는 문자 집합 표준이다. 8859-1(Latin 1)은 서유럽 문자를 담는다. VT의 8비트 문자열과 글꼴 종류가 이 계열을 쓴다.
35장에서 자세히
MSB와 LSB Most Significant Bit / Least Significant Bit · 최상위 비트와 최하위 비트
MSB는 값에서 가장 높은 자리, LSB는 가장 낮은 자리를 뜻한다. 비트에도 바이트에도 쓴다. ISOBUS 문서에서는 바이트 안의 비트 8이 MSB, 비트 1이 LSB다.
리틀 엔디언 순서라서, 여러 바이트로 된 값은 LSB 바이트를 먼저 보낸다.
4장에서 자세히
OSI 7계층 Open Systems Interconnection reference model
통신 기능을 물리, 데이터 링크, 네트워크, 전송, 세션, 표현, 응용의 7개 층으로 나눠 설명하는 참조 모델이다. 표준마다 어느 층의 일을 맡는지 비교할 때 쓴다.
19장에서 자세히
shall과 should
표준 문장의 요구 수준을 나타내는 말이다. shall은 반드시 지켜야 하는 요구이고, shall not은 금지이며, should는 따르지 않아도 위반은 아닌 권장이다.
19장에서 자세히
SIL Software-in-the-Loop
실제 장비 대신 소프트웨어로 상대 장치를 흉내 내어 시험하는 방식이다. 예를 들어 TC 서버나 VT를 프로그램으로 흉내 내 작업기 소프트웨어를 검증한다.
30장에서 자세히
Unicode와 UTF Unicode / UTF-8 / UTF-16
Unicode는 세계의 문자에 번호를 붙인 표준이고, UTF-8과 UTF-16은 그 번호를 바이트로 적는 방식이다. ISOBUS의 WideString은 UTF-16을 리틀 엔디언으로 쓰고, ISOXML 파일은 UTF-8을 쓴다.
35장에서 자세히
네트워크 계층 network layer
여러 버스 구간(세그먼트) 사이에서 메시지를 넘기고 거르는 일을 맡는 계층이다. ISOBUS에서는 ISO 11783-4가 정하고 NIU가 이 일을 한다.
21장에서 자세히
노드 node
버스에 연결된 장치 하나, 또는 장치가 버스에 물리적으로 붙는 지점이다. ISO 11783은 한 네트워크 구간에 노드를 30개까지 둘 수 있게 한다.
노드 수는 전기적 연결의 수다. ECU 하나가 CF를 여러 개 담아도 노드는 하나로 센다.
3장에서 자세히
니블 nibble
바이트의 절반인 4비트 묶음이다. 16진수 한 자리가 니블 하나다. 바이트의 비트 8~5를 상위 니블, 비트 4~1을 하위 니블이라 부른다.
TC의 Process Data 메시지처럼 한 바이트를 니블 둘로 나눠 서로 다른 값을 담는 메시지가 많다.
46장에서 자세히
대역폭 bandwidth
통신 선로가 일정 시간에 나를 수 있는 데이터의 양이다. 메시지를 많이, 자주 보낼수록 남는 대역폭이 줄어든다.
8장에서 자세히
데이터 링크 계층 data link layer
프레임을 만들고, 누가 버스를 쓸지 정하고, 오류를 검출해 데이터를 믿을 수 있게 옮기는 계층이다. CAN 규격과 ISO 11783-3이 이 층을 맡는다.
8장에서 자세히
디지털 신호 digital signal
0과 1 두 상태만으로 정보를 나타내는 신호다. 전압이 조금 흔들려도 0인지 1인지만 가리면 되므로 잡음에 강하다.
1장에서 자세히
리틀 엔디언 little endian
여러 바이트로 된 수를 낮은 자리 바이트부터 적거나 보내는 순서다. 0x1234는 34 12 순서가 된다. ISOBUS의 수치 값은 대부분 이 순서를 따른다.
반대로 높은 자리 바이트부터 적는 순서를 빅 엔디언이라 한다. 문자열은 엔디언과 상관없이 왼쪽 글자부터 보낸다.
23장에서 자세히
메시지 message
장치가 다른 장치에 전하는 정보 한 건이다. ISO 11783에서는 같은 PGN의 정보를 나르는 CAN 데이터 프레임 1개 이상을 메시지라 한다.
18장에서 자세히
물리 계층 physical layer
비트를 실제 전기 신호로 바꿔 전선으로 나르는 일을 정하는 계층이다. 전압, 케이블, 커넥터가 여기에 속하며, ISOBUS에서는 ISO 11783-2가 맡는다.
3장에서 자세히
바이트 byte
비트 8개를 묶은 단위다. 0~255(16진수로 00~FF)를 나타낼 수 있고, CAN 프레임의 데이터 길이도 바이트로 센다.
ISOBUS 문서는 데이터의 바이트를 Byte 1부터 센다. 프로그램 배열로는 data[0]이 Byte 1이다.
4장에서 자세히
버스 bus
여러 장치가 함께 쓰는 하나의 통신 선로다. 한 장치가 보낸 메시지를 버스에 붙은 모든 장치가 받고, 각자 필요한 것만 골라 쓴다.
버스 양 끝에는 신호 반사를 막는 종단 저항을 단다.
1장에서 자세히
버스 부하 bus load
버스가 프레임을 나르느라 쓰이는 시간의 비율이다. 높아질수록 우선순위가 낮은 메시지가 늦어지므로, 메시지를 설계할 때 여유를 남긴다.
8장에서 자세히
병렬 통신 parallel communication
여러 비트를 여러 선으로 동시에 보내는 통신 방식이다. 가까운 거리에서는 빠르지만 선이 많이 들고, 거리가 길면 선마다 도착 시각이 어긋나 오류가 난다.
1장에서 자세히
부호 있는 정수 signed integer
음수도 나타낼 수 있는 정수 형식이다. 보통 2의 보수로 음수를 적는다. 예를 들어 8비트 값 FF는 부호 없는 정수로 255, 부호 있는 정수로 −1이다.
분해능 resolution
원시값 1이 실제 값으로 얼마인지 나타내는 배율이다. 예를 들어 분해능이 0.125 rpm/bit이면 원시값 8000은 1000 rpm이다.
실제 값 = 원시값 × 분해능 + 오프셋으로 계산한다. 분해능과 단위는 SPN이나 DDI마다 정해져 있다.
9장에서 자세히
브로드캐스트 broadcast
받는 이를 정하지 않고 버스의 모든 장치에게 보내는 전송이다. 각 장치는 필요한 것만 골라 쓴다. J1939에서는 PDU2 메시지나 목적지 주소 255(Global)로 보낸 메시지가 브로드캐스트다.
2장에서 자세히
비트 bit
0 또는 1 하나를 나타내는 가장 작은 정보 단위다. 비트 8개를 묶으면 1바이트가 된다.
ISOBUS 문서는 한 바이트 안의 비트를 가장 낮은 자리인 비트 1부터 가장 높은 자리인 비트 8까지 번호로 부른다.
1장에서 자세히
비트레이트 bit rate · 통신 속도
1초에 보내는 비트 수다. 단위는 bit/s(bps)이고, ISOBUS는 250 kbit/s(초당 25만 비트)를 쓴다. 빠를수록 버스를 길게 깔기 어렵다.
3장에서 자세히
비휘발성 메모리 non-volatile memory
전원이 꺼져도 내용이 지워지지 않는 저장 장치(플래시 메모리 등)다. VT가 오브젝트 풀을 저장해 두거나, CF가 클레임한 주소를 기억해 둘 때 쓴다.
31장에서 자세히
상태 머신 state machine · 상태 기계
장치가 지금 어떤 상태인지와, 어떤 일이 생기면 어느 상태로 옮겨 가는지를 정해 둔 동작 모델이다. 연결 절차나 오류 처리를 구현할 때 쓴다.
53장에서 자세히
아날로그 신호 analog signal
전압처럼 끊김 없이 이어지는 값으로 정보를 나타내는 신호다. 전선에 잡음(노이즈)이 섞이면 값 자체가 틀어진다.
1장에서 자세히
액추에이터 actuator
전기 신호를 받아 실제 움직임을 만드는 부품이다. 밸브, 모터, 유압 실린더가 예다.
22장에서 자세히
오프셋 offset
기준값에 더하거나 빼는 값이다. 예를 들어 원시값에 오프셋 −40을 더해 실제 온도를 구하고, 기준점에서 떨어진 거리를 오프셋으로 적는다.
J1939 값은 보통 실제 값 = 원시값 × 분해능 + 오프셋으로 계산한다.
9장에서 자세히
응용 계층 application layer
메시지가 무슨 뜻이고 언제 어떻게 쓰는지를 정하는 맨 위 계층이다. VT, TC, 트랙터-작업기 메시지 같은 ISOBUS 규칙 대부분이 여기에 속한다.
18장에서 자세히
전송 계층 transport layer
큰 데이터를 조각으로 나눠 보내고 받는 쪽에서 다시 모으는 일을 맡는 계층이다. J1939와 ISOBUS의 TP, ETP가 하는 일이 이 층에 가깝다.
8장에서 자세히
전원 사이클 power cycle
장치의 전원을 껐다가 다시 켜는 한 번의 과정이다. 전원 사이클 뒤에도 남아야 하는 값(주소, 오브젝트 풀 등)은 비휘발성 메모리에 둔다.
31장에서 자세히
직렬 통신 serial communication
비트를 한 줄로 하나씩 차례대로 보내는 통신 방식이다. 선이 적게 들고 먼 거리에 유리하다. CAN도 직렬 통신이다.
1장에서 자세히
체크섬 checksum
데이터가 바뀌지 않았는지 확인하려고 데이터로 계산해 덧붙이는 값이다. 받는 쪽이 같은 계산을 해서 결과가 다르면 데이터가 손상된 것으로 본다.
CAN의 CRC도 체크섬의 한 종류다. NAME management는 대상 CF의 NAME으로 계산한 checksum으로 명령 대상이 맞는지 확인한다.
14장에서 자세히
클라이언트와 서버 client / server
서비스를 쓰는 쪽을 클라이언트, 제공하는 쪽을 서버라 한다. 예를 들어 작업기 ECU는 VT, TC, File Server의 클라이언트다.
타임아웃 timeout
기다리기로 정한 시간이 지나도록 응답이나 다음 메시지가 오지 않은 상황이다. 타임아웃이 나면 다시 보내거나 연결을 끊는 등 정해진 조치를 한다.
16장에서 자세히
토폴로지 topology
장치들이 통신 선로에 연결된 모양이다. CAN과 ISOBUS는 한 줄로 뻗은 주선에 장치들이 짧은 선으로 붙는 선형 버스 토폴로지를 쓴다.
20장에서 자세히
패딩 padding
정해진 길이를 맞추려고 남는 자리에 채워 넣는 값이다. ISOBUS에서는 8바이트보다 짧은 메시지나 마지막 TP 패킷의 남는 바이트를 FF로 채운다.
4장에서 자세히
패킷 packet
여러 프레임으로 나눠 보내는 긴 메시지의 조각 하나(CAN 프레임 하나)다. TP에서는 패킷마다 데이터를 7바이트씩 싣는다.
데이터가 프레임 하나에 다 들어가면 패킷이 곧 메시지다.
15장에서 자세히
페이로드 payload
프레임에서 머리와 꼬리를 뺀, 실제로 전하려는 데이터 부분이다. 고전 CAN 프레임의 페이로드는 최대 8바이트, CAN FD는 최대 64바이트다.
1장에서 자세히
프레임 frame
버스 위로 한 번에 보내는 전송 단위다. 보낸 이와 내용 종류를 알려 주는 머리, 실제 데이터, 오류 검사 코드로 이뤄진다. 편지 봉투 하나에 비유할 수 있다.
4장에서 자세히
프로토콜 protocol
장치끼리 데이터를 어떤 형식, 순서, 의미로 주고받을지 미리 정한 약속이다. CAN, J1939, ISOBUS가 모두 프로토콜이다.
1장에서 자세히
흐름 제어 flow control
받는 쪽이 감당할 수 있는 만큼만 보내도록 보내는 양과 속도를 맞추는 장치다. TP의 CMDT에서는 받는 쪽이 CTS로 한 번에 받을 패킷 수를 정한다.
15장에서 자세히

CAN

ACK Acknowledgement · 확인 응답
CAN에서는 프레임을 제대로 받은 노드가 ACK 슬롯에 0을 써서 "받았다"고 알리는 비트다. J1939와 ISOBUS에서는 명령이나 요청을 처리했다는 응답 메시지(PGN 59392의 긍정 응답)를 뜻한다.
CAN의 ACK 슬롯은 아무 노드나 채울 수 있어서, 목적지 장치가 받았는지까지는 알려 주지 않는다. 그 확인은 응용 계층의 Acknowledgement 메시지로 한다.
6장에서 자세히
ACK 에러 ACK Error
보낸 프레임의 ACK 슬롯을 아무 노드도 0으로 채우지 않았을 때 보낸 노드가 잡는 오류다. 버스에 혼자 있거나 선이 끊긴 경우에 난다.
6장에서 자세히
BRS Bit Rate Switch
CAN FD 프레임에서 데이터 구간을 더 빠른 속도로 보낼지 알리는 비트다. 이 비트 뒤부터 속도가 바뀐다.
7장에서 자세히
Bus Off 버스 오프
TEC가 255를 넘으면 들어가는 상태로, 노드가 버스에서 완전히 빠져 보내지도 받지도 않는다. 1이 11개 이어지는 구간을 128번 확인하면 다시 Error Active로 돌아올 수 있다.
6장에서 자세히
CAN Controller Area Network
자동차와 농기계의 ECU들이 두 가닥 선 하나를 함께 쓰며 메시지를 주고받는 직렬 통신 규격이다. Bosch가 만들었고 ISO 11898로 표준화됐다.
받는 이 주소 대신 메시지 ID로 내용을 구분하고, 여러 노드가 동시에 보내면 ID가 작은 메시지가 먼저 나간다. ISOBUS는 CAN 위에서 동작한다.
2장에서 자세히
CAN FD CAN with Flexible Data-Rate
고전 CAN을 넓힌 규격으로, 프레임당 데이터를 최대 64바이트까지 싣고 데이터 구간을 더 빠른 속도로 보낸다. ISO 11783은 ISOBUS 네트워크에서 CAN FD 프레임을 쓰지 말라고 정한다.
8바이트보다 큰 ISOBUS 데이터는 CAN FD 대신 TP나 ETP로 나눠 보낸다.
7장에서 자세히
CAN 컨트롤러 CAN controller
ECU 안에서 CAN 프레임을 만들고 받으며, 중재와 오류 검출을 하드웨어로 처리하는 회로다. 소프트웨어는 컨트롤러가 받아 둔 프레임을 꺼내 쓴다.
오류 카운터(TEC, REC)와 에러 상태도 컨트롤러가 관리한다. 소프트웨어가 프레임을 늦게 꺼내면 버퍼에서 덮여 사라질 수 있다.
4장에서 자세히
CAN_H와 CAN_L
CAN 버스를 이루는 두 신호선이다. 두 선의 전압 차이로 0과 1을 나타낸다. 0(Dominant)이면 CAN_H는 올라가고 CAN_L은 내려가 차이가 약 2 V가 된다.
1(Recessive)이거나 버스가 비어 있으면 두 선 모두 약 2.5 V라 차이가 거의 없다.
3장에서 자세히
candump
리눅스 SocketCAN 도구 모음(can-utils)에 든 프로그램으로, 버스에 흐르는 CAN 프레임을 화면에 찍거나 로그 파일로 저장한다.
로그 파일에는 프레임을 18EAFFFE#00EE00처럼 ID와 데이터를 #로 이어 적는다.
55장에서 자세히
CANopen
CAN 위에서 동작하는 산업 자동화용 상위 프로토콜이다. 공장 기계나 모터 제어에 많이 쓴다.
8장에서 자세히
CBFF Classical Base Frame Format · 고전 CAN 기본 프레임 형식
11비트 ID를 쓰는 고전 CAN 프레임 형식(표준 프레임)이다. ISOBUS 버스에서는 제조사 독점 메시지에만 쓸 수 있다.
11비트 ID에는 PGN이 없고 우선순위와 보낸 이의 주소만 들어간다.
5장에서 자세히
CEFF Classical Extended Frame Format · 고전 CAN 확장 프레임 형식
29비트 ID를 쓰는 고전 CAN 프레임 형식(확장 프레임)이다. ISOBUS의 표준 통신은 모두 이 형식을 써야 한다.
4장에서 자세히
CRC Cyclic Redundancy Check
보낸 데이터로 계산해 프레임에 붙이는 오류 검출 값이다. 받는 쪽이 같은 계산을 해서 값이 다르면 전송 중 손상된 것으로 본다. 고전 CAN은 15비트 CRC를 쓴다.
CAN FD는 데이터 길이에 따라 17비트나 21비트 CRC를 쓴다.
4장에서 자세히
CRC 에러 CRC Error
받은 데이터로 계산한 CRC가 프레임에 실린 CRC와 다를 때 받는 노드가 잡는 오류다.
6장에서 자세히
CSMA/CD+AMP
CAN이 버스를 쓰는 방식의 이름이다. 버스가 비었을 때 보내기 시작하고(CSMA), 충돌을 감지하며(CD), 메시지 우선순위로 승자를 정한다(AMP).
충돌이 나도 우선순위가 높은 메시지는 손상되지 않고 그대로 전송된다.
5장에서 자세히
DB9 커넥터
PC용 CAN 인터페이스나 진단 장비에 흔히 쓰는 9핀 D자형 커넥터다. 보통 7번 핀이 CAN_H, 2번 핀이 CAN_L, 3번 핀이 GND다.
3장에서 자세히
DeviceNet
CAN 위에서 동작하는 공장 자동화용 상위 프로토콜이다. 센서와 액추에이터를 잇는 네트워크에 쓴다.
8장에서 자세히
DLC Data Length Code
CAN 프레임의 데이터가 몇 바이트인지 알려 주는 4비트 값이다. 고전 CAN에서는 0~8바이트를 나타낸다.
ISOBUS에서는 길이가 정해진 짧은 메시지는 그 길이를 DLC로 쓰고(Request는 3), 여러 프레임으로 갈 수 있는 메시지는 DLC 8에 남는 바이트를 FF로 채운다.
4장에서 자세히
Dominant 우세
CAN 버스에서 논리 0 상태다. 두 선 사이에 전압 차가 생긴 상태이고, 한 노드라도 0을 보내면 버스 전체가 0이 된다. 그래서 0이 1을 이긴다.
3장에서 자세히
EOF End of Frame / End of File
CAN 프레임에서는 프레임 끝을 알리는 1(Recessive) 비트 7개다. File Server 이야기에서는 파일의 끝(End of File)을 뜻한다.
4장에서 자세히
Error Active 에러 활성
오류 카운터가 낮은(TEC, REC 모두 128 미만) 정상 상태다. 오류를 발견하면 0 6개(Active Error Flag)로 버스 전체에 강하게 알린다.
6장에서 자세히
Error Passive 에러 패시브
TEC나 REC가 128 이상인 제한 상태다. 오류를 알릴 때 1 6개(Passive Error Flag)를 보내므로 다른 노드의 통신을 방해하지 못하고, 이어서 보내기 전에 조금 더 기다린다.
6장에서 자세히
ESI Error State Indicator
CAN FD 프레임에서 보내는 노드가 Error Active(0)인지 Error Passive(1)인지 알리는 비트다.
7장에서 자세히
FD Tolerant와 FD Active
FD Tolerant 노드는 CAN FD 프레임을 직접 주고받지는 못하지만 지나가는 FD 프레임을 에러 없이 무시한다. FD Active 노드는 CAN FD 프레임을 주고받을 수 있다.
고전 CAN만 아는 노드는 CAN FD 프레임을 에러로 본다.
7장에서 자세히
FDF FD Format
프레임이 CAN FD 형식인지 알려 주는 비트다. 1이면 CAN FD 프레임이다. ISOBUS에서는 0(Dominant)으로 고정해 고전 CAN 프레임만 쓴다.
7장에서 자세히
IDE Identifier Extension
CAN ID가 11비트 표준형(0)인지 29비트 확장형(1)인지 알려 주는 비트다. ISOBUS는 29비트 확장형을 쓴다.
4장에서 자세히
ISO 11898
CAN을 정하는 국제 표준 묶음이다. 11898-1은 프레임과 오류 처리 같은 데이터 링크 규칙을, 11898-2는 고속 물리 계층을 정한다.
ISOBUS 장치의 CAN 인터페이스는 ISO 11898-1:2015와 ISO 11898-2:2016을 따른다.
2장에서 자세히
LIN과 FlexRay
CAN과 비교되는 차량용 통신 규격이다. LIN은 선 한 가닥으로 창문, 좌석 같은 느린 기능을 잇는 값싼 규격이고, FlexRay는 높은 안전성이 필요한 곳에 쓰는 빠르고 비싼 규격이다.
2장에서 자세히
Recessive 열세
CAN 버스에서 논리 1 상태다. 두 선의 전압이 같은 상태이고, 모든 노드가 1을 보낼 때만 버스가 1이 된다. 버스가 비어 있을 때도 이 상태다.
3장에서 자세히
RTR Remote Transmission Request
CAN 프레임이 데이터 프레임(0)인지 리모트 프레임(1)인지 가르는 비트다. ISOBUS는 리모트 프레임을 쓰지 않으므로 늘 0으로 보낸다.
4장에서 자세히
SOF Start of Frame
CAN 프레임의 시작을 알리는 첫 비트다. 항상 0(Dominant) 하나이고, 버스의 노드들이 이 비트에 박자를 맞춘다.
4장에서 자세히
SRR Substitute Remote Request
29비트 확장 프레임에서 표준 프레임의 RTR 자리에 들어가는 비트다. 항상 1(Recessive)이다.
4장에서 자세히
TEC와 REC Transmit Error Counter / Receive Error Counter · 송신·수신 오류 카운터
CAN 컨트롤러가 세는 송신 오류 카운터(TEC)와 수신 오류 카운터(REC)다. 오류가 나면 크게(보통 8) 늘고 성공하면 1씩 줄며, 이 값으로 에러 상태가 정해진다.
6장에서 자세히
Wired-AND
여러 노드의 출력이 한 선에서 AND 연산처럼 합쳐지는 동작이다. 누구 하나라도 0(Dominant)을 내면 선 전체가 0이 된다. CAN 중재가 이 성질을 이용한다.
3장에서 자세히
고전 CAN Classical CAN
CAN FD와 구별해 부르는 기존 CAN이다. 프레임당 데이터가 최대 8바이트이고 속도는 최대 1 Mbit/s다. ISOBUS는 고전 CAN만 쓴다.
CAN 2.0A(11비트 ID)와 CAN 2.0B(29비트 ID)는 고전 CAN 규격의 옛 판 이름이다.
7장에서 자세히
기아 상태 starvation
우선순위가 높은 메시지가 너무 자주 나가서, 우선순위가 낮은 메시지가 계속 중재에 져 오래 나가지 못하는 상태다.
5장에서 자세히
데이터 프레임 Data Frame
실제 데이터를 실어 나르는 CAN 프레임이다. ISOBUS 통신은 모두 데이터 프레임으로 한다.
4장에서 자세히
리모트 프레임 Remote Frame
데이터 없이 ID만 보내 "이 ID의 데이터를 보내 달라"고 요청하는 CAN 프레임이다. ISOBUS에서는 쓰지 않고, 대신 Request 메시지(PGN 59904)로 요청한다.
ISOBUS의 ID에는 보낸 이의 주소가 들어가므로, 남의 주소를 단 리모트 프레임으로는 요청할 수 없기 때문이다.
4장에서 자세히
멀티마스터 multi-master
정해진 지휘자 없이 버스의 어떤 노드든 원할 때 먼저 보낼 수 있는 방식이다. 동시에 보내면 중재로 순서를 정한다.
2장에서 자세히
비트 스터핑 bit stuffing
같은 값의 비트가 5개 이어지면 반대 값 비트 하나를 끼워 넣는 CAN 규칙이다. 신호가 자주 바뀌어야 받는 쪽이 박자를 잃지 않기 때문이다. 받는 쪽은 끼운 비트를 빼고 읽는다.
4장에서 자세히
비트 에러 Bit Error
보내는 노드가 자기가 보낸 비트와 버스에서 읽은 비트가 다를 때 잡는 오류다. 단, 중재 구간과 ACK 슬롯에서 1을 보내고 0을 읽는 것은 정상이다.
6장에서 자세히
비파괴적 중재 non-destructive arbitration
중재에서 이긴 메시지는 중간에 깨지지 않고 그대로 전달되고, 진 노드도 데이터를 잃지 않고 버스가 비면 다시 보내는 CAN 중재의 성질이다.
5장에서 자세히
상위 프로토콜 higher-layer protocol
CAN처럼 데이터를 나르는 아래 계층 위에서, 메시지의 뜻과 주고받는 규칙을 정하는 프로토콜이다. J1939, CANopen, ISOBUS가 CAN의 상위 프로토콜이다.
8장에서 자세히
스터프 에러 Stuff Error
같은 값 비트가 6개 연속으로 오는 등 비트 스터핑 규칙이 깨졌을 때 받는 노드가 잡는 오류다.
6장에서 자세히
스텁 stub · 분기선
버스 주선에서 각 ECU로 갈라져 나가는 짧은 선이다. 길면 신호 반사가 생기므로 짧게 둔다.
3장에서 자세히
에러 프레임 Error Frame
오류를 발견한 노드가 버스 전체에 알리려고 보내는 특별한 비트 묶음이다. 받던 프레임은 모두 버리고, 보낸 노드는 다시 보낸다.
에러 플래그(같은 값 비트 6개)와 에러 구분자(1 8개)로 이뤄진다.
6장에서 자세히
오버런 overrun
받는 쪽 소프트웨어가 수신 버퍼를 제때 비우지 못해 새 프레임이 이전 프레임을 덮어쓰는 일이다. 버스에 에러 프레임을 남기지 않아 보낸 쪽은 알 수 없다.
6장에서 자세히
오버로드 프레임 Overload Frame
노드가 아직 다음 프레임을 받을 준비가 안 됐을 때 다음 전송을 잠시 늦추는 CAN 프레임이다.
4장에서 자세히
접지 ground (GND)
회로 전압의 기준이 되는 0 V 선이다. 접지 연결이 나쁘면 CAN 파형의 전압 레벨이 틀어진다.
3장에서 자세히
종단 저항 termination resistor
버스 양 끝에 하나씩 다는 120 Ω 저항이다. 선 끝에서 신호가 되튀는 반사를 막는다. 두 개가 병렬이라 CAN_H와 CAN_L 사이를 재면 약 60 Ω이 정상이다.
ISOBUS는 단순 저항 대신 기준 전압까지 잡아 주는 TBC(종단 바이어스 회로)를 쓴다.
3장에서 자세히
중재 arbitration
여러 노드가 동시에 보내려 할 때 누가 버스를 쓸지 정하는 과정이다. CAN에서는 ID를 비트 단위로 비교해 값이 작은 쪽이 이기고, 주소 클레임에서는 NAME 값이 작은 쪽이 주소를 얻는다.
CAN 중재에서 진 노드는 이긴 프레임을 망가뜨리지 않고 조용히 물러났다가 다시 시도한다.
5장에서 자세히
중재 구간과 데이터 구간 Arbitration phase / Data phase
CAN FD 프레임의 두 속도 구간이다. 중재 구간은 모든 노드가 같은 기본 속도로 보내고, BRS가 켜지면 데이터 구간을 더 빠른 속도로 보낸다.
두 구간을 서로 다른 속도로 보내는 방식을 듀얼 비트레이트라 하고, 두 속도를 Nominal Bit Rate와 Data Bit Rate라 부른다.
7장에서 자세히
차동 신호 differential signaling
두 선의 전압 차이로 정보를 나르는 방식이다. 바깥 잡음은 두 선에 똑같이 실리므로, 차이만 보면 잡음이 지워진다.
3장에서 자세히
트랜시버 transceiver
ECU 안에서 CAN 컨트롤러가 정한 0과 1을 CAN_H·CAN_L 전압으로 바꾸고, 반대로 버스 전압을 0과 1로 읽어 주는 칩이다.
3장에서 자세히
특성 임피던스 characteristic impedance
빠르게 변하는 신호가 전선을 지날 때 느끼는 그 선로 고유의 저항값이다. CAN 케이블은 120 Ω이라 양 끝에 같은 값의 종단 저항을 단다.
3장에서 자세히
폼 에러 Form Error · 형식 에러
항상 1이어야 하는 자리(CRC 구분자, ACK 구분자, EOF)에서 0을 받았을 때 잡는 오류다.
6장에서 자세히

SAE J1939

29비트 ID 29-bit identifier
CAN 확장 프레임의 ID다. J1939와 ISOBUS는 이 29비트를 우선순위 3비트, EDP 1비트, DP 1비트, PF 8비트, PS 8비트, SA 8비트로 나눠 읽는다.
예를 들어 0x18FEEE00은 우선순위 6, PGN 65262, SA 0이다.
9장에서 자세히
Abort 중단
TP와 ETP에서는 연결을 중간에 끝내는 Connection Abort 메시지(control byte 255)로, 타임아웃 같은 사유 코드를 함께 보낸다. Sequence Control에서는 기록이나 재생을 즉시 멈춘 상태를 뜻한다.
Connection Abort는 Byte 2에 사유 코드를 싣고, 보내는 쪽과 받는 쪽 모두 보낼 수 있다.
16장에서 자세히
Access Denied
요청을 알아듣고 지원도 하지만 허락하지 않는다는 거절 응답이다. J1939 Acknowledgement의 응답 종류(control byte 2)이고, NIU 연결 거절과 File Server 오류 코드에도 같은 이름이 쓰인다.
10장에서 자세히
Acknowledgement Acknowledgement (PGN 59392) · 확인 응답 메시지
명령이나 요청에 대한 응답 메시지(PGN 59392)다. 첫 바이트(control byte)로 ACK(처리함), NACK(못 함), Access Denied(거부), Cannot Respond(바빠서 나중에)를 가른다.
10장에서 자세히
Address Claimed
"이 주소를 내가 쓰겠다"고 자기 NAME과 함께 모두에게 알리는 메시지(PGN 60928)다. 같은 주소를 두 CF가 원하면 NAME 값이 작은 쪽이 이긴다.
13장에서 자세히
BAM Broadcast Announce Message
TP로 여러 프레임짜리 데이터를 모두에게 보낼 때 먼저 보내는 안내 메시지다. 전체 바이트 수, 패킷 수, PGN을 알린 뒤 TP.DT를 차례로 보낸다. 받는 쪽은 확인이나 재전송 요청을 하지 않는다.
15장에서 자세히
Cannot Claim Address
주소를 얻지 못한 CF가 보낸 이 주소 254(NULL)로 자기 NAME을 실어 보내는 메시지다. Address Claimed와 PGN이 같고, SA가 254인 것으로 구별한다.
13장에서 자세히
Cannot Respond
지원하지만 지금은 바빠서 응답할 수 없으니 나중에 다시 요청하라는 Acknowledgement 응답(control byte 3)이다.
10장에서 자세히
CMDT Connection Mode Data Transfer
TP에서 상대 하나와 연결을 맺고 보내는 방식이다. 보내는 쪽이 RTS로 요청하면 받는 쪽이 CTS로 몇 패킷씩 받을지 정하고, 다 받으면 EndOfMsgACK로 끝낸다. 빠진 패킷은 다시 요청할 수 있다.
15장에서 자세히
Commanded Address
다른 CF(주로 서비스 툴)가 특정 NAME의 CF에게 새 주소를 쓰라고 명령하는 메시지(PGN 65240)다. 데이터가 9바이트라 BAM으로 모두에게 보낸다.
명령을 받아들인 CF는 새 주소로 Address Claimed를 보낸다. 지원은 선택 사항이다.
13장에서 자세히
commanding CF와 target CF
NAME management에서 NAME 변경을 명령하는 쪽(서비스 툴, NIU 등)을 commanding CF, NAME이 바뀌는 쪽을 target CF라 부른다.
14장에서 자세히
Control byte
메시지 첫 바이트에 두어 같은 PGN 안에서 메시지 종류를 가르는 값이다. 예를 들어 TP.CM에서는 16이 RTS, 17이 CTS, 32가 BAM이고, Acknowledgement에서는 0이 ACK, 1이 NACK이다.
15장에서 자세히
CTS Clear To Send
CMDT에서 받는 쪽이 "몇 번 패킷부터 몇 개 보내라"고 허락하는 메시지(TP.CM의 control byte 17)다. 개수가 0인 CTS는 연결을 유지한 채 잠시 멈추라는 뜻(hold)이다.
"이 번호부터 보내라"는 말은 그 앞 번호까지는 잘 받았다는 확인도 겸한다.
15장에서 자세히
current NAME과 pending NAME
current NAME은 CF가 지금 Address Claimed로 내보내는 NAME이고, pending NAME은 NAME management로 받은 새 값을 채택 명령 전까지 보관해 둔 NAME이다.
14장에서 자세히
DA Destination Address · 목적지 주소
메시지를 받을 CF의 주소다. PDU1 메시지의 PS 자리에 들어가고, 255(Global)면 모두에게 보낸다는 뜻이다.
9장에서 자세히
Device Class
NAME의 7비트 필드로, 장비의 큰 종류(트랙터, 파종기, 분무기 등)를 나타낸다. Industry Group과 함께 읽어야 뜻이 정해진다. J1939에서는 Vehicle System이라 부른다.
12장에서 자세히
Device Class Instance
NAME의 4비트 필드로, 같은 종류(device class)의 장비가 여럿 연결됐을 때 몇 번째인지 나타낸다. J1939의 Vehicle System Instance와 같다.
12장에서 자세히
DP Data Page
29비트 ID 안의 1비트로, PGN 공간을 0쪽과 1쪽 두 페이지로 나눈다. EDP와 함께 쓴다.
8장에서 자세히
DPO Data Packet Offset
ETP에서 데이터 패킷 묶음을 보내기 전에 "이번 묶음의 번호는 이 오프셋부터 센다"고 알리는 메시지(ETP.CM의 control byte 22)다. 순서 번호가 1바이트뿐이라 큰 번호를 이렇게 나눠 센다.
17장에서 자세히
ECU Instance
NAME의 3비트 필드로, 한 기능을 여러 ECU가 나눠 맡을 때 그중 몇 번째 ECU인지 나타낸다.
12장에서 자세히
EDP Extended Data Page
29비트 ID 안의 1비트로, DP와 함께 PGN이 속한 페이지를 고른다. ISO 11783 메시지는 보낼 때 항상 0으로 둔다.
EDP와 DP가 모두 1인 프레임은 ISO 15765-2(진단 통신) 프레임이라 PGN으로 해석하지 않는다.
8장에서 자세히
EEC1 Electronic Engine Controller 1
엔진 회전수, 토크 같은 엔진 상태를 담는 J1939 메시지(PGN 61444, 0xF004)다. 엔진 회전수(SPN 190)는 0.125 rpm/bit로 읽는다.
55장에서 자세히
EndOfMsgACK End of Message Acknowledgement
CMDT에서 받는 쪽이 데이터를 모두 받았다고 알리는 마지막 메시지(TP.CM의 control byte 19)다. ETP에서는 EOMA(23)라 부른다.
16장에서 자세히
error indicator 오류 지시값
센서나 장치 오류로 지금은 올바른 값을 보낼 수 없다는 뜻의 특수값이다. 1바이트 값이면 FE, 2바이트 값이면 FExx다.
값이 유효한데 범위만 넘으면 이 값 대신 최솟값이나 최댓값을 보낸다. FMI 2, 3, 4 같은 고장에서는 방송 값을 이 값으로 바꿔 보낸다.
28장에서 자세히
ETP Extended Transport Protocol · 확장 전송 프로토콜
1785바이트보다 큰 데이터(최대 117,440,505바이트)를 보내는 ISOBUS의 전송 규칙이다. CMDT처럼 상대 하나와 연결해서만 보내며, VT 오브젝트 풀처럼 큰 데이터를 옮길 때 쓴다.
TP와 달리 SAE J1939와 맞춰진 규칙이 아니고 ISO 11783에만 있다. 모두에게 보내는 BAM 방식은 없다.
17장에서 자세히
ETP.CM ETP Connection Management
ETP의 연결 관리 메시지(PGN 51200)다. 첫 바이트로 RTS(20), CTS(21), DPO(22), EOMA(23), Abort(255)를 가른다.
17장에서 자세히
ETP.DT ETP Data Transfer
ETP에서 데이터를 나르는 메시지(PGN 50944)다. TP.DT처럼 첫 바이트가 1~255 순서 번호이고, 실제 패킷 번호는 DPO가 알려 준 오프셋에 이 번호를 더해 구한다.
17장에서 자세히
Function Instance
NAME의 5비트 필드로, 같은 기능을 하는 CF가 여럿일 때 몇 번째인지 나타낸다. 예를 들어 function instance 0인 VT가 주(primary) VT이고, TC 번호도 이 값으로 가린다.
12장에서 자세히
Function(NAME 필드)
NAME의 8비트 필드로, CF가 하는 일(엔진, VT, TC 등)을 나타내는 코드다. 0~127은 산업 공통 의미이고, 128~253은 device class에 따라 뜻이 달라진다.
12장에서 자세히
GE Group Extension
PDU2 메시지에서 PS 자리에 들어가 PGN을 더 잘게 나누는 8비트 값이다. PF와 합쳐 메시지 종류를 정한다.
9장에서 자세히
Global 주소 Global Address · 전역 주소
목적지 주소 255(0xFF)로, 네트워크의 모든 CF를 뜻한다. 목적지로만 쓰고 보낸 이 주소로는 쓰지 않는다.
12장에서 자세히
Group function
PGN 하나에 여러 기능을 묶는 메시지 형식이다. 어떤 기능인지는 보통 데이터 첫 바이트로 가른다. VT, TC, File Server, Sequence Control 메시지와 TP.CM이 이 방식이다.
같은 group function PGN은 CAN ID가 같으므로 데이터 길이를 하나로 정해 둔다. Acknowledgement의 Group Function Value는 어느 하위 기능에 대한 응답인지 알려 준다.
10장에서 자세히
hold 전송 잠시 멈춤
CMDT에서 받는 쪽이 패킷 수 0인 CTS, 곧 CTS(0)를 보내 연결은 연 채 전송을 잠시 멈추는 것이다. 0.5초(Th)마다 되풀이해야 하고, 보내는 쪽은 1.05초(T4) 안에 다음 CTS가 없으면 연결을 닫는다.
16장에서 자세히
Identity Number
NAME의 21비트 필드로, 제조사가 자기 제품마다 붙이는 일련번호다. 같은 제조사 제품끼리 NAME이 겹치지 않게 한다.
12장에서 자세히
Industry Group
NAME의 3비트 필드로, 장비가 속한 산업 분야를 나타낸다. 0은 전 산업 공통, 2는 농업·임업 장비다.
12장에서 자세히
initial address 초기 주소
CF가 전원을 켤 때 처음 클레임을 시도하는 주소다. 주소 경쟁이나 Commanded Address로 다른 주소를 얻으면, 그 주소를 다음 전원 인가 때의 initial address로 저장한다.
14장에서 자세히
J1939 SAE J1939
트럭, 버스, 농기계 같은 대형 차량의 ECU가 CAN 위에서 대화하는 방법을 정한 SAE 표준이다. 29비트 ID를 우선순위, 메시지 종류(PGN), 보낸 이 주소로 나눠 쓴다. ISOBUS의 바탕이다.
J1939-21(데이터 링크), J1939-71(차량 메시지), J1939-73(진단)처럼 여러 문서로 나뉜다.
8장에서 자세히
Manufacturer Code 제조사 코드
NAME의 11비트 필드(0~2047)로, 표준 관리 기관이 제조사마다 배정한 번호다.
12장에서 자세히
NACK Negative Acknowledgement · 부정 응답
메시지를 이해하지 못했거나 요청한 일을 할 수 없다는 응답이다. 특정 주소로 받은 요청이 지원하지 않는 PGN이면 NACK을 보내고, 전체(Global) 요청에는 보내지 않는다.
10장에서 자세히
NAME
CF마다 붙는 64비트(8바이트) 고유 이름이다. 기능, 산업 분야, 제조사 코드, 일련번호 등을 담는다. 주소가 겹치면 이 값이 작은 쪽이 이기고, 주소가 바뀌어도 NAME은 그대로라 상대를 알아보는 기준이 된다.
12장에서 자세히
NAME checksum
NAME 변경 명령에 싣는 1바이트 값으로, 대상 CF의 원래 NAME 8바이트를 더한 합의 하위 8비트다. 그사이 주소가 다른 CF에게 넘어갔다면 명령이 엉뚱한 CF에 적용되지 않게 막는다.
14장에서 자세히
NAME management NAME management (NM)
실행 중에 CF의 NAME 일부(주로 instance 필드)를 바꾸는 절차와 메시지(PGN 37632)다. 새 값은 pending NAME으로 보관했다가 채택 명령이 오면 쓰고, 새 NAME으로 주소를 다시 클레임한다.
14장에서 자세히
Non-configurable
주소를 바꿀 수 없는 CF의 주소 구성 능력이다. 원하는 주소를 못 얻으면 Cannot Claim Address를 보낸다. ISO 11783에서는 옛 장비와 호환하려고 받아 줄 뿐이다.
13장에서 자세히
Not available 사용 불가 값
값이 없거나 보낼 수 없음을 나타내는 특수값이다. 1바이트 값이면 FF(255), 2바이트 값이면 가장 높은 바이트가 FF인 값을 쓴다. 가장 높은 바이트가 FE면 오류가 있다는 error indicator다.
1바이트 값은 0~250(00~FA)만 실제 값이다. 받는 쪽은 이런 특수값을 측정값으로 계산하면 안 된다.
23장에서 자세히
NULL 주소 Null Address
아직 주소를 얻지 못한 CF가 쓰는 보낸 이 주소 254(0xFE)다. Request for Address Claimed와 Cannot Claim Address를 보낼 때만 쓸 수 있다.
12장에서 자세히
originating CF와 receiving CF
TP 연결에서 RTS를 보내 데이터를 보내는 쪽을 originating CF, CTS를 보내 데이터를 받는 쪽을 receiving CF라 부른다.
16장에서 자세히
PDU Protocol Data Unit · 프로토콜 데이터 단위
한 번에 주고받는 데이터 묶음을 가리키는 말이다. J1939에서는 29비트 ID(우선순위, PGN, SA)와 최대 8바이트 데이터로 된 CAN 프레임 하나를 뜻한다.
8장에서 자세히
PDU1
PF 값이 240 미만인 J1939 메시지 형식이다. PS에 목적지 주소를 넣어 특정 CF(또는 255로 전체)에게 보낸다.
9장에서 자세히
PDU2
PF 값이 240 이상인 J1939 메시지 형식이다. 목적지 없이 모두에게 보내고, PS는 PGN을 세분하는 GE로 쓴다.
9장에서 자세히
PF PDU Format
29비트 ID 안의 8비트 필드로, 메시지 종류를 정하는 PGN의 핵심 부분이다. 240 미만이면 PDU1(목적지 지정), 240 이상이면 PDU2(브로드캐스트)다.
9장에서 자세히
PG Parameter Group · 파라미터 그룹
함께 보내는 값(파라미터)들을 한 메시지로 묶은 것이다. 예를 들어 엔진 회전수와 토크를 한 PG로 보낸다. PG마다 번호(PGN)가 붙는다.
측정값뿐 아니라 명령, 요청, ACK, NACK도 PG다. 누가 보내든 같은 PG는 같은 형식이다.
9장에서 자세히
PGN Parameter Group Number · 파라미터 그룹 번호
메시지(PG)의 종류를 가리키는 번호다. 29비트 ID의 EDP, DP, PF, PS(GE)로 만들며, 예를 들어 PGN 59904는 Request 메시지다.
PDU1 메시지는 PS가 목적지 주소이므로 PGN을 셀 때 PS 자리를 0으로 둔다. 데이터 안에 PGN을 적을 때는 3바이트를 낮은 자리부터 적는다.
9장에서 자세히
preferred address 선호 주소
표준이 기능별로 미리 정해 둔 주소다. 예를 들어 VT는 38(0x26), TC는 247(0xF7)이다. 다만 주소에 우선권은 없고, 상대 기능은 주소가 아니라 NAME으로 판단해야 한다.
12장에서 자세히
Priority 우선순위
J1939에서는 29비트 ID 맨 앞의 3비트 우선순위 필드로, 0이 가장 높고 7이 가장 낮다. VT에서는 Alarm Mask의 우선순위 속성(0 높음, 1 중간, 2 낮음)을 뜻한다.
J1939 우선순위는 중재에만 쓰이고 받는 쪽은 무시한다. 제어용 메시지는 기본 3, 정보성 메시지와 요청은 기본 6, TP와 ETP는 7이다.
5장에서 자세히
Proprietary A, A2, B 제조사 독점 메시지
데이터 내용을 제조사가 마음대로 정하는 메시지 자리다. A(PGN 61184)와 A2(126720)는 목적지를 지정하고, B(65280~65535)는 모두에게 보낸다.
같은 PGN이라도 제조사마다 뜻이 다르므로, 보낸 장치의 NAME에 든 제조사 코드로 누구 메시지인지 확인하는 편이 안전하다.
10장에서 자세히
PS PDU Specific
29비트 ID 안의 8비트 필드다. PDU1이면 받는 쪽 주소(DA)이고, PDU2이면 PGN의 일부(GE)다.
9장에서 자세히
qualifier flag
NAME management 메시지의 비트 8개로, NAME 필드마다 하나씩 붙어 그 필드를 바꿀지, 오류 원인인지, 검색 조건에 쓸지를 표시한다. 뜻은 모드마다 다르다.
14장에서 자세히
Request Request (PGN 59904) · 요청
다른 CF에게 특정 PGN을 보내 달라고 요청하는 메시지(PGN 59904)다. 데이터 3바이트에 원하는 PGN을 담는다. ISOBUS는 리모트 프레임 대신 이 메시지로 요청한다.
특정 주소로 받은 요청에는 반드시 답하고, 지원하지 않으면 NACK을 보낸다. 응답은 200 ms 안에 해야 한다.
10장에서 자세히
Request for Address Claimed
지금 어떤 주소를 누가 쓰고 있는지 묻는 Request 메시지다. 받은 CF는 모두 Address Claimed로 답하므로, 새로 들어온 CF가 빈 주소를 찾을 때 쓴다.
13장에서 자세히
Request2
응답 방식을 더 자세히 지정할 수 있는 확장 요청 메시지(PGN 51456)다. 응답을 Transfer 메시지로 받게 하거나, 데이터 첫 바이트 값으로 원하는 하위 기능만 고를 수 있다.
11장에서 자세히
RTS Request To Send
CMDT에서 보내는 쪽이 "이만큼 보내도 되나" 묻는 연결 시작 메시지(TP.CM의 control byte 16)다. 전체 바이트 수, 패킷 수, 보낼 PGN을 담는다. ETP에도 같은 역할의 RTS(20)가 있다.
CTS 하나가 허락할 수 있는 최대 패킷 수도 함께 알린다.
15장에서 자세히
RTxD Random Transmit Delay · 무작위 송신 지연
0~255 난수에 0.6 ms를 곱한 무작위 대기 시간(최대 153 ms)이다. 여러 CF가 동시에 켜져도 주소 클레임 메시지가 같은 순간에 겹치지 않게 한다.
13장에서 자세히
SA Source Address · 소스 주소
메시지를 보낸 CF의 8비트 주소로, 29비트 ID 맨 끝 8비트에 들어간다. 0~253을 쓰고, 254는 주소를 얻지 못했을 때, 255는 목적지 전용(전체)이다.
주소는 바뀔 수 있으므로 상대가 누구인지는 SA가 아니라 NAME으로 판단한다.
12장에서 자세히
SAE SAE International (Society of Automotive Engineers)
미국에서 시작한 자동차·이동 기계 기술자 단체로, J1939 같은 차량 통신 표준을 만든다.
8장에서 자세히
Self-configurable address 자기 구성 주소 능력
NAME 맨 앞 1비트이자, 주소 경쟁에서 지면 스스로 다른 주소(주로 128~247)를 골라 다시 클레임하는 능력이다. ISO 11783을 따르는 CF는 이 능력을 갖춰야 한다.
J1939에서는 같은 비트를 AAC(Arbitrary Address Capable)라 부른다.
13장에서 자세히
SPN Suspect Parameter Number
메시지 안에 든 값 하나하나(엔진 회전수, 냉각수 온도 등)에 붙인 번호다. 바이트 위치, 길이, 분해능, 오프셋과 함께 정의되고, 고장 코드에서 어느 값에 문제가 있는지 가리킬 때도 쓴다.
SPN은 19비트다. 예를 들어 SPN 110은 엔진 냉각수 온도다.
9장에서 자세히
TP Transport Protocol · 전송 프로토콜
8바이트를 넘는 데이터(9~1785바이트)를 7바이트씩 여러 CAN 프레임으로 나눠 보내고 다시 모으는 규칙이다. 모두에게 보내는 BAM과 상대 하나와 흐름을 맞추는 CMDT 두 방식이 있다.
15장에서 자세히
TP.CM TP Connection Management
TP의 연결 관리 메시지(PGN 60416)다. 첫 바이트(control byte)로 BAM, RTS, CTS, EndOfMsgACK, Abort를 가른다.
Byte 6~8에는 지금 나르는 데이터의 PGN을 싣는다.
15장에서 자세히
TP.DT TP Data Transfer
TP에서 실제 데이터를 나르는 메시지(PGN 60160)다. 첫 바이트가 순서 번호(1~255)이고 나머지 7바이트가 데이터이며, 마지막 패킷의 남는 바이트는 FF로 채운다.
15장에서 자세히
Tr, T1~T4, Th 응답·전송 타이머
요청·응답과 TP에서 얼마나 기다릴지 정한 시간 값들이다. Tr(200 ms)은 응답해야 하는 시간, T3(1.25 s)은 응답을 기다리는 최소 시간, T1(750 ms)은 다음 데이터 패킷을 기다리는 시간이다.
T2(1.25 s)는 CTS 뒤 첫 데이터 패킷을, T4(1.05 s)는 CTS(0) 뒤 다음 CTS를 기다리는 시간이다. Th(500 ms)는 연결을 멈춰 둘 때 CTS(0)를 다시 보내는 주기다.
16장에서 자세히
Transfer Transfer (PGN 51712)
Request2에 대한 응답 메시지(PGN 51712)다. 데이터 묶음마다 그 데이터의 주인 CF를 표시해, 한 CF가 여러 CF의 정보를 대신 보고할 수 있게 한다.
11장에서 자세히
가상 연결 virtual connection
큰 메시지 하나를 옮기려고 두 CF가 잠시 맺는 연결 관계다. 선을 새로 잇는 것이 아니라, 같은 버스 위에서 서로 연결 중이라고 기억하는 약속이다.
16장에서 자세히
멀티패킷 메시지 multi-packet message
데이터가 8바이트를 넘어 CAN 프레임 여러 개로 나눠 보내는 메시지다. 모든 프레임의 ID는 같고 데이터만 다르며, TP나 ETP로 보낸다.
반복 주기가 100 ms 이하인 메시지는 멀티패킷으로 정의할 수 없다.
15장에서 자세히
목적지 지정 메시지 destination-specific message
받을 CF 하나를 주소로 정해 보내는 메시지다. J1939에서는 PDU1 형식에서 PS에 목적지 주소를 넣어 보낸다. 같은 메시지를 255(Global)로 보내면 모두가 받는다.
9장에서 자세히
세션 session
두 CF가 큰 데이터 하나를 주고받으려고 잠시 맺는 연결 한 번이다. TP 세션 하나는 메시지 하나를 옮기고 끝나면 닫힌다. OSI 7계층에서는 다섯 번째 층(세션 계층)의 이름이다.
한 CF는 같은 상대에게 TP 연결을 동시에 하나만 열 수 있다. 데이터 패킷에 PGN이 없어서 무엇의 조각인지 구별할 수 없기 때문이다.
16장에서 자세히
시퀀스 번호 sequence number
여러 조각으로 나눠 보낸 데이터에서 각 조각의 순서를 알려 주는 번호다. TP.DT와 ETP.DT는 첫 바이트에 1~255를 싣고, Heartbeat도 시퀀스 번호로 통신이 살아 있는지 확인한다.
15장에서 자세히
예약 reserved
표준이 나중을 위해 비워 둔 비트나 값이다. 보낼 때는 표준이 정한 값(대부분 비트 1, 바이트면 FF)으로 채우고, 받을 때는 그 자리에 의미를 두지 않는다.
NAME의 예약 비트처럼 0으로 두라고 정한 곳도 있으니 메시지마다 정의를 확인한다.
주소 구성 능력 address configuration capability
CF가 주소를 정하는 방식의 종류다. 기본 능력은 non-configurable과 self-configurable이고, 확장 능력으로 service-configurable과 command-configurable이 있다.
service-configurable은 서비스 기사가 정비 모드에서 주소를 바꾸는 능력이고, command-configurable은 Commanded Address로 언제든 주소를 바꾸는 능력이다. 확장 능력은 NAME에 드러나지 않는다.
13장에서 자세히
주소 위반 address violation
두 CF가 같은 보낸 이 주소를 쓰고 있는 상태다. 자기 주소로 온 일반 메시지를 받은 CF는 Address Claimed를 다시 보내고, SPN 2000+주소, FMI 31인 고장 코드를 켠다.
14장에서 자세히
주소 클레임 address claim
CF가 쓸 주소를 정하고 네트워크에 알리는 절차다. 쓰이는 주소를 묻고 기다린 뒤 Address Claimed를 보내고, 겹치면 NAME을 비교해 진 쪽이 다른 주소를 고르거나 물러난다.
Address Claimed를 보낸 뒤 250 ms 동안 경합이 없으면 그 주소를 확보한 것이고, 그 전에는 다른 메시지를 보내지 않는다.
13장에서 자세히
주소-NAME 대응표
Address Claimed 응답을 모아 만든 "어느 주소를 어느 NAME의 CF가 쓰는지" 목록이다. 같은 주소에 다른 NAME이 나타나면 이전 상대가 바뀌었음을 알 수 있다.
13장에서 자세히
확장 식별자 extended identifier
Request2에 적는 1~3바이트 값이다. 요청한 PGN의 데이터 첫 1~3바이트가 이 값인 메시지만 골라 달라는 필터로, Group function의 특정 하위 기능을 요청할 때 쓴다.
11장에서 자세히

ISOBUS 공통

4선 꼬임 케이블 quad-twisted wire cable
전선 네 가닥을 함께 꼰 케이블이다. ISOBUS 네트워크 구간은 이 케이블 한 가닥으로 이루어지고, ECU는 짧은 선으로 여기에 붙는다.
3장에서 자세히
AEF Agricultural Industry Electronics Foundation
농기계 제조사들이 만든 국제 단체로, ISOBUS 장비의 적합성 시험과 인증을 맡는다. 장비 전체가 아니라 UT, TC-BAS, AUX-N 같은 기능 단위로 인증한다.
18장에서 자세히
CF Control Function · 제어 기능
ECU 안에서 특정 일을 맡는 기능 단위로, 메시지를 보내고 받는 주체다. 네트워크에서 주소 하나와 NAME 하나를 가지며, ECU 한 대가 CF 여러 개를 담을 수 있다.
예를 들어 VT와 관리 게이트웨이를 한 ECU에 담으면 그 ECU 안에 NAME과 주소가 둘씩 있다.
18장에서 자세히
ECU_PWR과 PWR
트랙터가 커넥터로 작업기에 주는 두 전원이다. ECU_PWR은 작업기 ECU와 센서용, PWR은 밸브나 모터 같은 액추에이터용이다. 켜고 끄는 일은 TECU가 맡는다.
22장에서 자세히
filter database 필터 데이터베이스
NIU가 포트 쌍(port pair)마다 어떤 PGN을 통과시키고 막을지 적어 둔 규칙표다. block 모드는 적힌 PGN만 막고, pass 모드는 적힌 PGN만 통과시킨다.
21장에서 자세히
forwarding과 filtering
forwarding은 한 구간에서 받은 프레임을 다른 구간으로 넘기는 일이고, filtering은 filter database에 따라 PGN별로 통과시키거나 막는 일이다. NIU의 기본 작업이다.
21장에서 자세히
generation 세대
같은 기능성 안에서 기능 묶음의 세대를 나타내는 번호다. Control function functionalities 메시지에 기능성 코드와 함께 실린다. TC 기능성은 지금 모두 generation 1이다.
28장에서 자세히
head-of-line blocking 줄 앞 막힘
줄 맨 앞의 메시지 때문에 뒤에 선 급한 메시지까지 기다리는 현상이다. NIU가 들어온 순서대로만 내보내는 단순 FIFO 큐를 쓰면 안 되는 이유다.
21장에서 자세히
IBBC Implement Bus Breakaway Connector · 작업기 버스 분리 커넥터
트랙터 뒤에서 작업기의 ISOBUS 케이블을 꽂는 9핀 커넥터다. CAN 신호선, 작업기용 전원, 종단 회로 신호가 지나가며, 작업기가 떨어져 나가도 트랙터 쪽 버스는 계속 동작하게 설계된다.
20장에서 자세히
ISO 11783
ISOBUS를 정하는 국제 표준으로, 여러 Part로 나뉜다. 예를 들어 Part 3은 데이터 링크, Part 5는 네트워크 관리, Part 6은 VT, Part 7은 작업기 메시지, Part 10은 TC를 정한다.
Part 1(총론)부터 Part 14(Sequence Control)까지 있다. 정식 제목은 "농업·임업용 트랙터와 기계: 직렬 제어 통신 데이터 네트워크"다.
18장에서 자세히
ISO 11783 데이터베이스 isobus.net
표준에 따라 배정된 PGN, NAME의 기능 코드, 선호 주소, 제조사 코드, DDI 등을 모아 공개하는 온라인 목록이다(isobus.net).
새 코드가 필요하면 이 데이터베이스에 있는 신청 양식으로 관리 기관에 요청한다.
19장에서 자세히
ISOBUS
트랙터와 작업기가 제조사와 상관없이 서로 통신하도록 정한 국제 표준 ISO 11783을 부르는 이름이다. CAN과 J1939를 바탕으로 VT, TC 같은 농기계용 기능을 더했다.
목표는 상호운용성이다. 어느 회사 트랙터에 어느 회사 작업기를 붙여도 같은 방식으로 통신해야 한다.
18장에서 자세히
MICS Mobile Implement Control System
ISO 11783 네트워크로 묶여 함께 동작하는 장비 전체(트랙터, 작업기, VT, TC 등)를 가리키는 공식 용어다. ISOXML 파일 이야기에서는 사무실의 FMIS와 대비되는 기계 쪽 시스템을 뜻한다.
18장에서 자세히
minimum control function 최소 제어 기능
모든 CF가 기본으로 갖춰야 하는 기능 묶음으로, 데이터 링크(ISO 11783-3), 네트워크 관리(-5), 진단(-12) 규칙을 말한다. VT나 TC 같은 기능은 그 위에 얹는다.
18장에서 자세히
Network message
NIU의 설정값, filter database, 연결 구조, 연결을 조회하고 바꾸는 메시지(PGN 60672)다. 첫 바이트 function code로 기능을 가른다.
21장에서 자세히
NIU Network Interconnection Unit · 네트워크 연결 장치
버스 구간(세그먼트)과 구간을 잇는 장치다. 하는 일에 따라 리피터, 브리지, 라우터, 게이트웨이, 트랙터 ECU로 나뉜다. 노드가 30개를 넘거나 구간을 서로 격리해야 할 때 쓴다.
21장에서 자세히
port pair 포트 쌍
NIU의 포트 두 개를 묶어 메시지가 어느 구간에서 어느 구간으로 흐르는지 나타낸 값이다. 한 바이트의 상위 니블이 출발 포트, 하위 니블이 도착 포트다.
21장에서 자세히
service provider 서비스 제공자
Working Set 바깥에서 Working Set에 서비스를 주는 CF다. VT와 TC가 대표적이다.
Working Set Member 메시지를 정해진 개수만큼 받지 못한 service provider는 master에게 Working Set 정의를 다시 요청한다.
26장에서 자세히
TAN Transaction Number · 거래 번호
명령과 응답의 짝을 맞추는 번호다. 보내는 쪽이 새 명령마다 번호를 바꾸고 받는 쪽이 응답에 그대로 돌려줘, 다시 보낸 명령이 두 번 실행되거나 늦은 응답과 섞이는 일을 막는다.
VT version 6의 활성화 메시지(4비트), File Server 명령, Sequence Control 명령에서 쓴다. 응답이 없어 다시 보낼 때는 같은 TAN을 쓰고, 받는 쪽은 같은 TAN을 보면 다시 실행하지 않고 이전 응답만 돌려준다.
51장에서 자세히
TBC Terminating Bias Circuit · 종단 바이어스 회로
ISOBUS 세그먼트 양 끝에 두는 능동 종단 회로다. 120 Ω 저항처럼 신호 반사를 막을 뿐 아니라 CAN_H와 CAN_L에 기준 전압도 잡아 준다.
20장에서 자세히
TECU Tractor ECU · 트랙터 ECU
트랙터 버스와 작업기 버스를 잇고, 작업기 버스에서 트랙터를 대표하는 장치다. 속도, PTO, 히치 같은 트랙터 정보를 작업기 쪽에 알리고, 클래스에 따라 작업기의 명령도 받는다.
작업기 쪽에서 보면 트랙터 정보는 모두 TECU의 주소로 나온다. 작업기 전원과 조명도 TECU가 관리한다.
22장에서 자세히
TECU 클래스 TECU class
TECU가 작업기 버스에 제공하는 기능 수준이다. Class 1은 기본 측정값, Class 2는 측정값 전체, Class 3은 히치·PTO·밸브 명령 수용까지다. 3GP처럼 기능 글자를 덧붙인다.
덧붙이는 글자는 N(항법), F(전방 히치·PTO), G(조향), P(속도·구동 전략 명령), M(발진 명령)이다.
22장에서 자세히
transit delay 통과 지연
메시지가 NIU를 지나 건너편 구간에 닿기까지 걸리는 시간이다. 브리지는 최대 10 ms가 권장된다.
21장에서 자세히
virtual CF 가상 CF
NIU가 다른 구간에 있는 실제 CF의 NAME으로 이쪽 구간에 세운 겉보기 CF다. 라우터 너머의 CF와 직접 통신해야 할 때 NIU 연결(connection)로 만든다.
21장에서 자세히
WideChar
문자 하나를 리틀 엔디언 2바이트로 적은 것이다. 예를 들어 A는 41 00이다. 16비트를 넘는 문자는 WideChar 두 개(surrogate pair)로 적는다.
35장에서 자세히
WideString
WideChar 0개 이상으로 된 문자열로, 항상 BOM(FF FE)으로 시작한다. 길이에는 BOM 2바이트가 들어가지만 글자 수에는 들어가지 않는다. VT와 File Server가 다국어 문자열에 쓴다.
예를 들어 "ABC"는 FF FE 41 00 42 00 43 00으로 8바이트이고, 보이는 글자는 3개다.
35장에서 자세히
Working Set 워킹 셋
작업기 하나의 기능을 함께 수행하는 CF들의 묶음이다. 그중 하나가 Working Set Master로서 VT, TC와의 통신을 대표한다. CF가 하나뿐이어도 Working Set이 된다.
줄여서 WS라고도 쓴다. VT와 TC는 마스터의 주소로 Working Set 전체와 통신한다.
26장에서 자세히
Working Set Master Working Set Master (WSM)
Working Set을 대표하는 CF다. 자기가 마스터라는 것과 구성원 수(자기 포함)를 알리고(PGN 65037), VT와 TC는 이 CF의 주소로 Working Set 전체와 통신한다.
Working Set Master 메시지와 Working Set Member 메시지를 모두 master가 직접 보낸다.
26장에서 자세히
Working Set Member
Working Set에 속한 나머지 CF다. 마스터가 Working Set Member 메시지(PGN 65036)로 구성원의 NAME을 하나씩 100 ms 간격으로 알린다.
member도 독립된 CF라 자기 주소로 고장 메시지를 보내고, 필요하면 VT에 직접 메시지를 보낼 수도 있다.
26장에서 자세히
게이트웨이 gateway
라우터 기능에 더해, 여러 메시지의 값을 꺼내 새 메시지로 다시 묶는(재포장) NIU다. 서로 다른 규칙의 네트워크를 이을 때 쓴다.
21장에서 자세히
기능성 functionality
사용자에게 제공되는 ISOBUS 기능의 단위다. UT(화면), TC-BAS, TC-GEO, TC-SC, AUX-N, TIM, ISB 등이 있고, AEF 인증과 Control function functionalities 메시지가 이 단위를 쓴다.
같은 기능성도 표준 개정에 따라 능력이 달라질 수 있어, 몇 번째 세대(generation)인지 함께 밝힌다.
부록에서 자세히
네트워크 관리 network management
CF가 주소를 얻고 지키고 바꾸는 절차 전체다. 주소 클레임, Commanded Address, NAME management, 주소 위반 처리가 여기에 들고, ISO 11783-5가 정한다.
26장에서 자세히
라우터 router
구간마다 주소 공간을 나누고 주소를 바꿔 메시지를 전달하는 NIU다. 주소 클레임 메시지가 라우터를 넘어가지 않는다.
21장에서 자세히
리피터 repeater
받은 비트 신호를 그대로 다른 구간으로 다시 내보내는 가장 단순한 NIU다. 아무것도 거르지 않으므로 모든 메시지가 지나간다.
21장에서 자세히
브리지 bridge
프레임을 저장했다가 다른 구간으로 내보내며, PGN 단위로 통과·차단(필터링)할 수 있는 NIU다. 주소 공간은 양쪽이 함께 써서 주소 클레임이 양쪽에 다 보인다.
21장에서 자세히
상호운용성 interoperability
제조사가 다른 장비끼리도 함께 맞물려 동작하는 성질이다. ISOBUS가 가장 중요하게 내세우는 목표다.
18장에서 자세히
세그먼트 network segment
양 끝이 종단 회로로 막힌, 하나로 이어진 버스 구간이다. 세그먼트끼리는 NIU로 잇는다.
ISOBUS의 기본 세그먼트는 트랙터 네트워크와 작업기 네트워크다.
19장에서 자세히
안전 상태 safe state
제어 시스템 일부나 전체가 고장 나도 사람에게 위험이 허용 수준인 동작 상태다. 통신이 끊기거나 감시 검사에 실패하면 작업기는 이 상태로 들어가야 한다.
25장에서 자세히
유지관리 기관 Maintenance Agency (MA)
ISO 11783 코드(PGN, NAME 기능 코드, 제조사 코드 등)의 새 등록과 갱신 요청을 처리하는 기관이다. isobus.net의 요청 양식으로 신청한다.
VDMA가 맡고, SAE J1939 위원회와 코드 등록을 맞춘다.
19장에서 자세히
작업기 버스 implement bus
트랙터 안에서 시작해 뒤쪽 커넥터를 지나 작업기까지 이어지는 ISOBUS 네트워크다. VT, TC, 작업기 ECU가 여기에 붙고, 여러 제조사 장비가 꽂히므로 ISO 11783을 반드시 따라야 한다.
20장에서 자세히
주소 공간 address space
같은 주소(SA) 번호 체계를 함께 쓰는 범위다. 브리지 양쪽은 주소 공간을 함께 쓰고, 라우터와 게이트웨이는 주소 공간을 나눈다.
21장에서 자세히
트랙터 버스 tractor bus
엔진, 변속기, 브레이크처럼 트랙터 자체 ECU들이 연결된 네트워크다. 트랙터 제조사가 관리하며, 작업기 버스와는 TECU로 분리된다.
20장에서 자세히

트랙터와 작업기

3점 히치 three-point hitch
트랙터 뒤(또는 앞)에서 아래쪽 링크 두 개와 위쪽 링크 하나로 작업기를 잡아 올리고 내리는 연결 장치다.
24장에서 자세히
Amd1 ISO 11783-7 Amendment 1 (2018)
ISO 11783-7 2015년판을 고친 2018년 개정이다. 히치 자세 메시지, Operator status 등을 더했다.
25장에서 자세히
Command와 Measured
Command 값은 보내는 쪽이 원하는 상태(요청)이고, Measured 값은 실제로 잰 현재 상태다. 트랙터는 명령을 무조건 따르지 않으므로, 작업기는 결과를 measured 메시지로 확인한다.
23장에서 자세히
DOP(PDOP, HDOP) Dilution of Precision · 정밀도 저하율
위성 배치 때문에 위치 정확도가 얼마나 떨어지는지 나타내는 지표다. 작을수록 정확하다. PDOP는 3차원 위치, HDOP는 수평 위치에 대한 값이다.
TimeLog 바이너리에는 0.1 단위 정수(u16)로 기록한다.
57장에서 자세히
exit/reason code 종료·사유 코드
트랙터가 작업기의 원격 명령을 받을 수 없는(또는 최근에 받기를 멈춘) 이유를 알리는 6비트 코드다.
24장에서 자세히
fast packet NMEA 2000 패스트 패킷
긴 NMEA 2000 메시지를 여러 프레임으로 나눠 보내는 방식이다. ISOBUS의 TP와 다르므로 따로 풀어야 한다. GNSS 위치 메시지가 이 방식으로 온다.
23장에서 자세히
GNSS와 GPS Global Navigation Satellite System / Global Positioning System
GNSS는 인공위성 신호로 위치를 재는 시스템을 통틀어 부르는 말이고, GPS는 그중 미국 시스템이다. TC는 이 위치로 섹션 제어와 위치별 살포량 제어를 한다.
ISOBUS 네트워크에서는 위치를 NMEA 2000 형식의 항법 메시지로 알린다.
41장에서 자세히
Ground-based speed 대지 속도
레이더 같은 센서로 땅을 기준으로 잰 실제 이동 속도와 거리다. 바퀴가 미끄러져도 영향을 받지 않는다. 트랙터가 100 ms마다 알린다.
23장에서 자세히
Heartbeat
통신 경로가 살아 있는지 확인하려고 CF가 보내는 1바이트 순서 번호 메시지(PGN 61668)다. 평소엔 보내지 않고, 받는 쪽이 요청하면 100 ms마다 보낸다. 번호가 어긋나면 받는 쪽은 안전 상태로 간다.
순서 번호는 초기화 때 251로 두고, 이후 0~250을 돌며 하나씩 올린다.
25장에서 자세히
Implement operating state command 작업기 작동 상태 명령
TECU가 작업기에게 지금 요구하는 운용 상태(밭 작업, 운반, 주차)를 1초마다와 바뀔 때 알리는 메시지(PGN 64771)다.
25장에서 자세히

Virtual Terminal(VT)

AID Attribute ID · 속성 번호
오브젝트의 속성(배경색, 너비, 값 등) 하나를 가리키는 번호다. Change Attribute 명령이 이 번호로 바꿀 속성을 고른다.
AID는 1바이트다. 읽기만 할 수 있는 속성도 있다.
33장에서 자세히
Alarm Mask 경보 마스크
경보가 생겼을 때 띄우는 화면 오브젝트다. 우선순위(높음, 중간, 낮음)와 경보음 설정을 가지며, 보통의 Data Mask보다 앞서 보인다.
우선순위 값은 0이 높음, 1이 중간, 2가 낮음이다. 가장 높은 경보는 그 Working Set이 마스크를 바꿀 때까지 화면에 남는다.
39장에서 자세히
AUX Auxiliary control · 보조 입력
조이스틱이나 보조 버튼 같은 입력 장치를 작업기 기능에 연결해 쓰는 VT 기능이다. 운전자가 VT 화면에서 어떤 입력으로 어떤 기능을 움직일지 할당한다.
옛 방식인 AUX-O(Type 1)와 새 방식인 AUX-N(Type 2)이 있다.
40장에서 자세히
AUX-O와 AUX-N
AUX-O(Type 1)는 VT version 2의 옛 보조 입력 방식이고, AUX-N(Type 2)은 version 3부터 쓰는 새 방식이다. 두 방식은 서로 호환되지 않으며, AUX-N은 입력 장치를 NAME으로 구별하고 지난 할당을 되살릴 수 있다.
40장에서 자세히
Auxiliary Assignment
VT가 어떤 보조 입력을 어떤 기능에 할당했는지(또는 할당을 풀었는지) 작업기에 알리는 명령이다.
40장에서 자세히
Auxiliary Function
작업기 쪽 오브젝트 풀에 두는, 보조 입력으로 조작할 수 있는 기능 하나를 정의한 오브젝트다. 기능의 종류(켜고 끄기, 아날로그 등)를 함께 적는다.
40장에서 자세히
Auxiliary Input
보조 입력 장치 쪽 오브젝트 풀에 두는, 버튼이나 레버 같은 조작구 하나를 정의한 오브젝트다.
40장에서 자세히
Auxiliary Input Status
보조 입력 장치가 버튼과 레버의 현재 값을 알리는 메시지다. AUX-N에서는 VT가 Status Enable로 허락해야 보내기 시작하고, 할당된 작업기는 이 값으로 기능을 움직인다.
40장에서 자세히
busy 비트
VT Status 메시지에 담긴, VT가 지금 무슨 일로 바쁜지 알리는 비트들이다. 마스크 갱신, 비휘발성 메모리 저장, 명령 실행, 매크로 실행, 풀 검사 등을 나타낸다.
31장에서 자세히
Button 버튼 오브젝트
화면 안에 그려 누를 수 있게 만든 버튼 오브젝트다. 누르면 VT가 Button Activation 메시지로 작업기에 알린다. 눌린 상태를 유지하는 래칭 버튼도 만들 수 있다.
33장에서 자세히
Button Activation
화면 버튼을 누르거나, 누르고 있거나, 뗄 때 VT가 작업기에 보내는 메시지다.
36장에서 자세히
Change Active Mask
Working Set이 보여 줄 화면(Data Mask나 Alarm Mask)을 바꾸는 명령이다. VT가 오류 때문에 스스로 마스크를 바꿨을 때는 VT Change Active Mask로 작업기에 알린다.
36장에서 자세히
Change Attribute
오브젝트의 속성 하나를 AID(속성 번호)로 골라 새 값으로 바꾸는 명령이다.
37장에서 자세히
Change Numeric Value
숫자 오브젝트나 Number Variable의 값을 바꾸는 명령이다. 작업기가 VT에 보내면 화면 값이 바뀐다. 반대로 운전자가 입력해 값이 바뀌면 VT가 VT Change Numeric Value로 작업기에 알린다.
36장에서 자세히
Change Priority
Alarm Mask의 우선순위(높음, 중간, 낮음)를 바꾸는 VT 명령이다.
37장에서 자세히
Change Soft Key Mask
Data Mask나 Alarm Mask에 짝지어 둔 Soft Key Mask를 다른 것으로 바꾸는 명령이다.
37장에서 자세히
Change String Value
글자 오브젝트나 String Variable의 내용을 바꾸는 명령이다. 운전자가 글자를 입력해 바꾸면 VT가 VT Change String Value로 작업기에 알린다.
37장에서 자세히
Colour Map
오브젝트에 적힌 색 번호를 다른 색 번호로 바꿔 보여 주는 표 오브젝트다. 색 수가 적은 VT에서 색이 알맞게 보이도록 맞출 때 쓴다.
화면 반전처럼 색 배치를 한꺼번에 바꿀 때 쓰고, 그 Working Set의 화면에만 적용된다.
34장에서 자세히
Colour Palette
색 번호마다 실제 색을 ARGB(투명도와 빨강·초록·파랑)로 새로 정의하는 오브젝트다(VT version 6). 반투명한 색도 만들 수 있다.
34장에서 자세히
Container
여러 오브젝트를 한 덩어리로 묶는 오브젝트다. 묶은 오브젝트들을 함께 옮기거나 Hide/Show Object 명령으로 한꺼번에 숨기고 보이게 할 수 있다.
33장에서 자세히
Control Audio Signal
VT에 경보음 같은 소리를 내라는 명령이다. 반복 횟수, 주파수, 켜짐·꺼짐 시간을 정한다. 소리 크기는 Set Audio Volume으로 정한다.
39장에서 자세히
Data Mask 데이터 마스크
작업기 화면의 본문 영역을 채우는 최상위 오브젝트다. 숫자 칸, 그림, 버튼 같은 오브젝트를 자식으로 담고, Working Set마다 한 번에 하나가 화면에 보인다.
Data Mask 영역은 정사각형이고 최소 200 × 200 픽셀이다. VT version 6부터는 최소 480 × 480이다.
30장에서 자세히
Delete Object Pool
VT 메모리에서 이 Working Set의 오브젝트 풀을 지우라는 명령이다.
이 명령을 보낸 뒤 연결 유지 메시지를 멈추면 VT는 비정상 종료 경보를 띄우지 않는다.
31장에서 자세히
designator
VT에서는 소프트 키 하나가 그려지는 화면 칸을 뜻한다. TC의 DDOP에서는 장치나 요소에 붙이는 표시용 이름 문자열을 뜻한다.
VT의 Soft Key designator는 최소 60 × 32 픽셀이다. DDOP의 designator는 UTF-8로 최대 32자다.
30장에서 자세히
ECU to VT와 VT to ECU
VT 통신에 쓰는 두 PGN이다. 작업기에서 VT로 가는 메시지는 PGN 59136(0xE700), VT에서 작업기로 가는 메시지는 PGN 58880(0xE600)을 쓴다.
36장에서 자세히
Enable/Disable Object
입력 칸이나 버튼을 운전자가 쓸 수 있게 하거나 못 쓰게 하는 명령이다.
37장에서 자세히
End of Object Pool
오브젝트 풀을 다 보냈다고 VT에 알리는 메시지다. VT는 풀을 검사(parsing)한 뒤 오류가 있으면 어느 오브젝트가 잘못됐는지 응답에 담아 돌려준다.
메시지 첫 바이트(VT function)는 0x12다.
35장에서 자세히
ESC Escape
입력 중인 칸의 편집을 취소하는 명령이다. 작업기가 보내면 VT가 입력을 멈추고, 운전자가 취소하면 VT가 VT ESC로 작업기에 알린다.
38장에서 자세히
Event ID
VT 이벤트(눌림, 화면에 나타남 등)마다 붙은 번호다. 오브젝트 레코드에 Event ID와 Macro ID를 짝지어 적으면 그 이벤트에 매크로가 걸린다.
38장에서 자세히
Extended Macro
매크로 번호를 16비트로 넓힌 방식이다(VT version 5 이상). 매크로를 256개보다 많이 쓸 수 있고, Execute Extended Macro 명령으로 직접 실행한다.
38장에서 자세히
External Object Pointer
다른 Working Set의 오브젝트 풀에 있는 오브젝트를 자기 화면에 보여 주는 포인터 오브젝트다(VT version 5 이상). Sequence Control 화면이 다른 장치의 그림을 보여 줄 때 쓴다.
보여 줄 수 있는 오브젝트는 상대가 External Object Definition으로 공개해 둔 것뿐이고, 상대는 NAME(External Reference NAME)으로 가리킨다.
53장에서 자세히
Font Attributes
글자의 색, 크기, 종류(문자 집합), 스타일을 정하는 속성 오브젝트다. 글자를 보여 주는 오브젝트들이 이것을 가리킨다.
33장에서 자세히
Font type 글꼴 문자 집합
Font Attributes 오브젝트의 속성으로, 8비트 문자열을 어느 ISO 8859 문자 표로 읽을지 정한다. 0은 Latin 1, 1은 Latin 9(유로 기호 포함)다.
35장에서 자세히
Function attributes
AUX 기능·입력 오브젝트의 1바이트 속성이다. 하위 5비트가 기능 종류이고, 나머지 비트가 안전에 중요한 조작인지, 할당을 제한하는지 같은 할당 조건을 정한다.
40장에서 자세히
Get Attribute Value
오브젝트 속성의 현재 값을 VT에 묻는 메시지다.
37장에서 자세히
Get Hardware
VT 화면의 크기(픽셀), 색 깊이, 터치·포인팅 같은 하드웨어 능력을 묻는 메시지다.
30장에서 자세히
Get Memory
작업기가 오브젝트 풀을 올리기 전에 VT의 버전과, 풀을 올릴 메모리가 남아 있는지 묻는 메시지다. 연결 초기에 가장 먼저 쓰는 기술 데이터 메시지다.
30장에서 자세히
Graphics Context
작업기가 명령으로 선, 도형, 글자를 직접 그려 넣는 캔버스 오브젝트다.
30장에서 자세히
Hide/Show Object
Container 오브젝트를 숨기거나 다시 보이게 하는 명령이다. 개별 오브젝트를 숨기려면 Container로 묶어 둬야 한다.
37장에서 자세히
Initiating 비트
Working Set Maintenance의 첫 메시지에만 1로 켜는 "지금 막 연결을 시작한다" 표시다. VT가 이 비트를 다시 보면 Working Set이 재시작한 것으로 보고 비정상 종료로 처리한다.
31장에서 자세히
Input Boolean
켜기와 끄기 두 값만 고르는 체크 칸 오브젝트다.
32장에서 자세히
Input List
목록에서 항목 하나를 고르게 하는 입력 오브젝트다. 고른 항목의 번호가 값이 된다.
33장에서 자세히
Input Number
운전자가 숫자를 입력하는 칸 오브젝트다. 값을 자기 안에 두거나 Number Variable을 가리킨다. 운전자가 값을 바꾸면 VT가 작업기에 새 값을 알린다.
33장에서 자세히
Input String
운전자가 글자를 입력하는 칸 오브젝트다. 입력이 끝나면 VT가 VT Change String Value 메시지로 작업기에 알린다.
38장에서 자세히
Key Group
키(Key 오브젝트)를 최대 4개 묶은 오브젝트다(VT version 4 이상). 운전자가 User-Layout 소프트 키 칸에 묶음째로 배치한다.
34장에서 자세히
latchable 래칭
한 번 누르면 눌린 상태로 남고, 다시 눌러야 풀리는 Button의 동작 방식이다.
33장에서 자세히
learn mode 학습 모드
운전자가 할당 화면에서 기능을 고른 뒤 실제 조작구를 움직여 입력을 지정하는 VT의 선택 기능이다. 이 모드 동안 작업기는 보조 입력으로 기능을 실행하면 안 된다.
40장에서 자세히
Line Attributes와 Fill Attributes
Line Attributes는 선의 색, 굵기, 무늬를, Fill Attributes는 도형 안을 채우는 방식(색, 무늬)을 정하는 속성 오브젝트다.
33장에서 자세히
Lock/Unlock Mask
여러 변경을 운전자에게 한 번에 보이게 하려고 화면 반영을 잠시 묶어 두는 명령이다(VT version 4 이상). 잠금이 풀릴 때 바뀐 내용이 한꺼번에 드러난다.
마스크가 보이는 중이면 Unlock 응답은 잠금 동안의 변경이 화면에 모두 반영된 뒤에 온다. 그래서 화면 반영 완료 확인으로도 쓴다.
37장에서 자세히
Model Identification Code
보조 입력 유닛 제조사가 정한 2바이트 모델 번호다. 같은 모델의 다른 유닛을 기능적으로 같다고 볼지 판단할 때 NAME과 함께 쓴다.
40장에서 자세히
momentary 비래치
누르는 동안만 켜지고 손을 떼면 저절로 꺼지는 키, 버튼, 조작구다. 누르고 있으면 VT가 200 ms마다 held를 알리고, 300 ms 넘게 끊기면 놓은 것으로 본다.
38장에서 자세히
multisound
여러 Working Set의 소리를 동시에 낼 수 있는 VT의 능력이다. 이 능력이 없는 VT는 경보음이 나면 다른 Working Set이 낸 소리를 끊는다.
39장에서 자세히
Navigating과 Data input
VT의 두 입력 상태다. Navigating은 운전자가 입력 칸과 버튼 사이에서 포커스를 옮기는 상태이고, Data input은 입력 칸 하나를 열어 값을 넣는 상태다.
38장에서 자세히
Number Variable
화면에 직접 보이지 않고 숫자 값만 담아 두는 오브젝트다. 여러 입력·출력 오브젝트가 같은 값을 함께 가리킬 수 있다.
값은 32비트다. 값을 한 번 바꾸면 이 변수를 가리키는 오브젝트가 모두 다시 그려진다.
33장에서 자세히
Object ID 오브젝트 번호
오브젝트 풀 안에서 오브젝트 하나를 가리키는 16비트 번호다. 명령으로 값이나 화면을 바꿀 때 이 번호로 대상을 고른다. VT에서는 65535(FFFF)가 "없음(NULL)"이다.
TC의 DDOP 오브젝트도 같은 이름의 16비트 번호로 서로를 가리킨다.
32장에서 자세히
Object Pointer
다른 오브젝트를 가리키는 자리표시 오브젝트다. 가리키는 대상만 바꾸면 화면의 그 자리 내용이 바뀐다.
가리키는 대상은 Change Numeric Value 명령으로 바꾼다.
33장에서 자세히
Object Pool Transfer
오브젝트 풀 바이트를 VT로 보내는 메시지다. 크면 TP나 ETP로 나눠 보내고, 풀을 여러 번에 나눠 보낼 수도 있다.
35장에서 자세히
Output Number
숫자를 화면에 보여 주는 오브젝트다. 정수 원시값에 오프셋과 배율을 적용하고 소수 자릿수를 정해 표시한다.
표시값 = (원시값 + 오프셋) × 배율이다. 같은 값을 여러 곳에 보이려면 Number Variable을 함께 가리킨다.
32장에서 자세히
Output String
글자를 화면에 보여 주는 오브젝트다. 글자의 모양은 Font Attributes 오브젝트를 가리켜 정한다.
32장에서 자세히
Picture Graphic
비트맵 그림을 담는 오브젝트다. 색 깊이(단색, 16색, 256색)를 고르고, 크기를 줄이려고 RLE 압축을 쓸 수 있다.
33장에서 자세히
Pointing Event
운전자가 터치 화면 같은 포인팅 장치로 화면을 눌렀을 때, 눌린 좌표를 VT가 작업기에 알리는 메시지다.
39장에서 자세히
Preferred Assignment

User-Layout

18장에서 자세히
VT Virtual Terminal · 가상 단말
운전석에 있는 ISOBUS 공용 화면 장치다. 작업기가 화면 구성(오브젝트 풀)을 올려 두면 VT가 그려 주고, 운전자가 누른 키나 입력값을 작업기에 전한다. 작업기마다 모니터를 따로 달 필요가 없다.
ISO 11783-6이 정한다. VT의 선호 주소는 38(0x26)이지만 상대는 주소가 아니라 NAME으로 찾아야 한다.

명령과 그 응답이 같은 코드를 쓰므로, 어느 쪽인지는 PGN(보내는 방향)으로 가린다.
37장에서 자세히
VT Number VT 번호
네트워크에 VT가 여럿일 때 운전자에게 보이는 VT 번호다. VT Number = Function Instance + 1(1~32)이고, function instance 0인 VT가 주(primary) VT다.
Identify VT 명령을 받으면 모든 VT가 자기 번호를 잠시 화면에 띄운다.
31장에서 자세히
VT Server와 VT Client
VT Server는 오브젝트 풀을 받아 화면을 그리고 운전자 입력을 받는 쪽, 곧 운전석의 VT 자체다. VT Client는 VT에 풀을 보내 자기 화면을 띄우는 작업기 ECU 쪽이다.
29장에서 자세히
VT Status
VT가 1초마다 모두에게 보내는 상태 메시지다. 지금 화면을 가진 Working Set, 보이는 마스크, 바쁜지 여부를 알린다. 3초 동안 오지 않으면 작업기는 VT와의 연결이 끊긴 것으로 본다.
31장에서 자세히
VT 버전 VT version
VT가 따르는 ISO 11783-6의 기능 수준을 나타내는 번호(2~6)다. 따로 협상하지 않으므로, 작업기는 VT의 버전을 확인하고 그 버전이 지원하는 오브젝트와 명령만 써야 한다.
예를 들어 Window Mask와 Key Group은 version 4부터, Colour Palette와 TAN은 version 6부터 쓸 수 있다.
29장에서 자세히
VT 이벤트 event (On Show, On Key Press 등)
오브젝트에 일어나는 일(보여짐, 숨겨짐, 키 눌림, 값 바뀜 등)이다. On Show, On Key Press처럼 부르며, 이벤트마다 매크로를 연결해 두면 그 일이 생길 때 매크로가 실행된다.
38장에서 자세히
Window Cell
User-Layout Data Mask를 2열 6행으로 나눈 한 칸이다. 칸 폭은 Data Mask 폭의 절반, 높이는 Data Mask 높이의 6분의 1(내림)이다.
34장에서 자세히
Window Mask
여러 작업기가 한 화면을 나눠 쓰는 User-Layout 화면에 작업기가 내놓는 작은 창 오브젝트다(VT version 4 이상). 모양이 정해진 표준 창과, 작업기가 자유롭게 꾸미는 창이 있다.
창의 크기는 픽셀이 아니라 Window Cell 칸 수로 정한다.
34장에서 자세히
Working Set Maintenance
Working Set이 VT에 1초마다 보내는 연결 유지 메시지다. 3초 동안 오지 않으면 VT는 그 Working Set과의 연결이 끊긴 것으로 본다. 첫 메시지에는 처음 연결한다는 표시와 자기 VT 버전을 싣는다.
31장에서 자세히
Working Set Special Controls
오브젝트 풀을 처음 그리기 전에 쓸 Colour Map, Colour Palette, 언어·국가 코드를 지정하는 오브젝트다(VT version 6). 풀에 하나까지 둘 수 있다.
34장에서 자세히
Working Set 오브젝트 Working Set object
오브젝트 풀의 맨 위 오브젝트다. VT의 작업기 고르기 화면에 보일 작은 표시(아이콘이나 이름)와, 처음 보여 줄 마스크를 정한다.
30장에서 자세히
그 밖의 출력 오브젝트 Output List, Output Meter, Output Line/Rectangle/Ellipse/Polygon, Bar Graph
값이나 모양을 화면에 그리는 VT 오브젝트들이다. Output List는 여러 항목 가운데 하나를, Output Meter는 바늘 계기를, 막대 그래프는 막대를 보여 주고, 선·사각형·타원·다각형 오브젝트는 도형을 그린다.
32장에서 자세히
그 밖의 화면 변경 명령 Change Child Location, Change Size, Change Background Colour, Change List Item
오브젝트의 위치, 크기, 배경색, 목록 항목을 바꾸는 VT 명령들이다. 예를 들어 Change Child Location은 부모 안에서 자식 오브젝트를 옮기고, Change Size는 크기를 바꾼다.
37장에서 자세히
기술 데이터 메시지 technical data messages
VT의 능력을 묻고 답하는 메시지 묶음이다. Get Memory(버전·메모리), Get Hardware(화면·색) 외에 소프트 키 수, 글꼴, 지원 문자 범위, 지원 오브젝트, 창 정보를 묻는 메시지가 있다.
Get Number of Soft Keys, Get Text Font Data, Get Supported WideChars, Get Supported Objects, Get Window Mask Data가 그 메시지들이다. 작업기는 답을 보고 오브젝트 풀을 VT에 맞춘다.

키가 많을 때 Soft Key 페이지를 넘기는 데 쓰는 물리 키다. 한 페이지에는 물리 키 수에서 내비게이션 키 수를 뺀 만큼의 키가 들어간다.

보조 입력 유닛 auxiliary input unit
조이스틱 같은 보조 조작구를 네트워크에 제공하는 장치(CF)다. 별도 ECU일 수도, VT 안에 있을 수도 있다. 살아 있음을 알리려고 100 ms마다 유지 메시지를 보낸다.
40장에서 자세히
소프트 키 soft key
화면 가장자리에 그려지고 화면마다 뜻이 바뀌는 버튼이다. 옆의 물리 버튼으로 누르거나 터치로 누른다. 누르면 VT가 Soft Key Activation 메시지로 작업기에 알린다.
키가 VT의 칸 수보다 많으면 VT가 페이지 넘김 키를 만들어 여러 쪽으로 보여 준다.

작업기 화면을 이루는 모든 오브젝트(마스크, 키, 숫자 칸, 그림 등)를 바이트로 묶은 데이터다. 작업기가 VT에 올리면 VT가 이것으로 화면을 그린다.
오브젝트마다 번호(Object ID)와 종류가 있고, 부모 오브젝트가 자식 오브젝트의 번호를 가리켜 화면 계층을 만든다.

클리핑 clipping
오브젝트가 정해진 영역 밖으로 그려지는 부분을 잘라 내는 것이다. Container, Button, Soft Key designator, Window Mask가 그 경계가 된다.
34장에서 자세히
표준 팔레트 standard colour palette
VT 색 번호 0~255에 실제 색을 정해 둔 기본 표다. 0~15는 이름 있는 16색이고, 232~255는 VT 제조사가 정하는 고유 색이다.
34장에서 자세히
활성화 메시지 activation messages
운전자 조작(키 누름, 값 입력, 입력 칸 이동 등)을 VT가 먼저 Working Set에 알리는 메시지 묶음이다. VT to ECU(PGN 58880)로 보내고 Working Set이 응답한다.
36장에서 자세히
활성화 코드 activation code
키나 버튼의 동작 상태 값이다. 0은 뗌(released), 1은 누름(pressed), 2는 계속 누름(held), 3은 누르다 취소(aborted)다. 누르고 있는 동안에는 200 ms마다 2를 다시 보낸다.
코드 3(취소)은 VT version 4부터 있다. 누르고 있다는 메시지가 300 ms 넘게 끊기면 작업기는 키가 떼어진 것으로 본다.

SC Sequence Control / Section Control
대개 Sequence Control(조작 순서를 기록했다가 다시 실행하는 기능)의 약자다. TC 이야기에서는 Section Control(섹션 제어)을 줄여 SC라고도 쓴다(TC-SC).
Sequence Control은 ISO 11783-14가 정하고, 기록과 재생을 이끄는 SCM과 기능을 가진 SCC로 이뤄진다.
