WebRTC와 AWS 관리형 WebRTC

WebRTC(Web Real-Time Communication)는 브라우저와 네이티브 앱이 플러그인 없이 서로 실시간으로 영상·음성·임의 데이터를 주고받게 하는 표준 기술이다. W3C가 JavaScript API를, IETF가 ICE·SRTP·DTLS·SCTP 같은 프로토콜 스택을 정의한다. 핵심은 가능하면 두 피어가 서버를 거치지 않고 직접 UDP로 연결해 지연을 수백 ms 이하로 낮추는 데 있다.

이 스터디는 카메라가 달린 디바이스(농기계·로봇)의 영상을 운영자 브라우저로 보고 원격으로 제어하는 시나리오를 기준으로 삼는다. 원리 → 프로토콜 → 아키텍처 → AWS 관리형 서비스 순서로 이어지며, 마지막 캡스톤에서 전체를 하나의 플랫폼 설계로 묶는다. 대상은 TCP/UDP/HTTP/WebSocket 기초가 있는 백엔드 개발자다. 개념 나열보다 "왜 그런가 · 트레이드오프 · 운영 함정 · 실전 코드와 설정"에 무게를 둔다.

이 스터디에서 배우는 것:

  • WebRTC 기초: 기존 스트리밍과 비교한 WebRTC의 위치, 핵심 API, 시그널링 서버 설계
  • 연결 수립: SDP와 Offer/Answer, NAT의 동작, STUN, ICE 후보 쌍, TURN 릴레이
  • 미디어와 데이터 전송: RTP/RTCP와 코덱, 혼잡 제어와 지연 예산, DTLS-SRTP 보안, DataChannel
  • 아키텍처와 운영: Mesh·SFU·MCU 토폴로지, 브라우저 밖 디바이스 구현, WHIP/WHEP, getStats 기반 디버깅
  • AWS KVS WebRTC: 시그널링 채널 구조와 API, 디바이스 C SDK, 뷰어·백엔드, 인제스트와 저장, 운영·보안·비용
  • Chime SDK·IVS: SFU 기반 관리형 서비스의 모델과 한계, 디바이스 영상 플랫폼 적합성
  • 캡스톤: 농기계 원격 영상·제어 플랫폼의 전체 설계

전체 구조

두 피어가 시그널링 서버로 SDP와 ICE 후보를 교환하고, STUN/TURN의 도움으로 연결 경로를 찾는다. 경로가 확정되면 미디어는 SRTP, 데이터는 SCTP로 DTLS 위에서 암호화되어 직접 흐른다. 직접 연결이 불가능하면 TURN 릴레이가 대신 중계한다.
