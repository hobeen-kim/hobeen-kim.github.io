ISO 11783-1: General standard for mobile data communication 정리

이 문서에 대해

ISO 11783-1 표준 원문을 학습 목적으로 재구성한 비공식 요약·해설이다. 규범적 판단이 필요할 때는 반드시 원문 표준을 확인해야 한다.

처음 읽는다면

이 페이지는 ISO 11783 시리즈의 총론(Part 1: 용어 정의, 네트워크 전체 구조, 파트 구성)을 원문의 절 구조대로 요약한 참고 자료다. 용어의 원래 정의나 네트워크 요구사항을 원문 순서로 확인하고 싶을 때 펼쳐 본다. 처음이라면 18장 ISOBUS 개요와 19장 ISO 11783 Part 1: 네트워크 요구사항과 공통 서비스를 먼저 읽는다.

개요

ISO 11783 시리즈는 농업·임업용 트랙터와 여기에 장착(mounted)·반장착(semi-mounted)·견인(towed)되거나 자주식(self-propelled)인 작업기(implement) 사이의 직렬 제어·통신 데이터 네트워크를 규정하는 표준이다. 흔히 ISOBUS라고 부르는 그 표준이다. 목적은 트랙터·작업기에 장착된 센서, 액추에이터, 제어 요소, 정보 저장·표시 장치 사이의 데이터 전송 방법과 형식을 표준화하여, 제조사가 달라도 상호 운용되는 개방형 시스템(OSI, Open System Interconnect)을 만드는 것이다.

Part 1(이 문서)은 시리즈 전체의 총론에 해당한다. 시리즈 공통의 용어 정의, OSI 7계층 모델과의 대응, 네트워크 전체 구조(트랙터 네트워크·작업기 네트워크), 주요 ECU 기능(VT, TECU, TC 등)의 개요, 그리고 파라미터·주소 할당을 관리하는 전자 데이터베이스 체계를 다룬다.

2판(2017)에서 바뀐 점

2007년 1판의 부속서 A~G에 나열되어 있던 모든 식별자(파라미터)가 온라인 전자 데이터베이스로 이관되었다. 이제 parameter group, address, identity 할당은 SAE에 공식 등록되며 SAE J1939 recommended practice의 일부로 관리된다. 문서 본문에는 목록 대신 데이터베이스 참조만 남았다.

SAE J1939와의 관계가 이 표준을 이해하는 핵심이다. ISO 11783은 ISO 11898-2(고속 CAN 물리 계층) 기반 통신 시스템이며, 상당 부분이 트럭·버스용으로 개발된 SAE J1939 문서 위에 세워졌다. 두 표준은 공동 작업으로 정비되어, J1939를 만족하는 전자 유닛을 최소한의 변경만으로 농업·임업 장비에 쓸 수 있도록 설계되었다. 주소·NAME·PGN 할당 레지스트리도 SAE J1939와 공유한다.

  • 작성 주체: ISO/TC 23(농림업용 트랙터·기계) / SC 19(농업 전자)
  • 유지관리 기관(MA) 사무국: DIN을 대신하여 VDMA(독일기계공업협회)가 수행
  • 공식 데이터베이스: ISOBUS 웹사이트(isobus.net)

적용 범위(Scope)와 인용 규격

Part 1의 scope는 "시리즈 전체가 무엇을 표준화하는지"와 "이 파트가 총론임"을 선언하는 수준이다. 애플리케이션 개발자 관점에서 중요한 내용은, 주소 할당·identity 할당·파라미터 정의의 현행 목록이 문서가 아니라 isobus.net 온라인 데이터베이스에 있고 SAE J1939에 공식 등록된다는 점이다.

인용 규격(normative references)은 세 가지다: ISO 11783 시리즈 전체, ISO 11898-1(CAN 데이터 링크 계층·물리 시그널링), ISO 11898-2(CAN 고속 매체 접근 유닛).

용어약어정의 요지

네트워크 구조와 요구사항 (Clause 6)

브로드캐스트 중심 설계 (6.1)

ISO 11783 네트워크(트랙터 네트워크·작업기 네트워크)에서는 다수의 메시지가 브로드캐스트된다. 데이터를 특정 목적지로 지정하지 않고 네트워크에 흘리므로, 어떤 CF든 별도의 요청 메시지 없이 그 데이터를 사용할 수 있다. 특정 CF에게 보내야 하는 메시지는 CAN 식별자 안에 destination address를 포함하는 목적지 지정 형식을 쓴다. 즉 메시지 형식은 global 목적지 형식과 destination-specific 형식 두 가지이며, proprietary 통신도 이 두 형식 중 하나로 허용된다.

네트워크 계층 (6.4, ISO 11783-4)

서로 다른 네트워크 아키텍처를 가진 두 네트워크를 연결할 때는, 통합자(integrator)가 network interconnect unit을 사용해 세그먼트를 상호 격리해야 한다. 또한 ISO 11783-2가 규정하는 세그먼트당 30노드 전기적 제한을 넘는 복잡한 시스템에서는, 작업기 제조사가 network interconnect unit으로 세그먼트를 분할하여 전기 부하 한도를 지켜야 한다.

네트워크 관리 (6.5, ISO 11783-5)

  • 네트워크에서 통신하는 모든 CF는 source address(SA)가 필요하다. 한 ECU가 여러 CF를 수행하면 CF마다 주소가 필요하다.
  • CF의 유일 식별을 위해 ISO 11783-5가 64-bit NAME을 규정한다. SA 결정 절차와 주소 충돌 해소 절차도 -5에 정의된다.
  • SA는 사전 설정(preset)되거나, 전원 인가 시 각 컨트롤러가 동적으로 클레임한다.
  • ISO 11783 네트워크에서 통신하는 모든 CF에는 NAME이 할당되어야 한다. VT와 management gateway를 한 ECU에 담는 경우처럼, 하나의 ECU 안에 여러 NAME·주소가 공존할 수 있다.
  • isobus.net 데이터베이스가 관리하는 항목: NAME 필드용 산업(industry) 코드, 비특정 CF용 preset/preferred address, 농림업 장비용 initial address 할당, CF가 사용할 NAME 목록, ECU 제조사 목록.

전형적 토폴로지(표준 Figure 3의 구조)에서는 트랙터 네트워크의 CF들(주소 예: 0, 3, 7, 30, 31, 35), tractor ECU(ECU 번호 7, 주소 240), 작업기 네트워크의 VT(38), management computer gateway(37), task controller(247), 그리고 작업기들의 CF(자기 구성 주소 a1~a4)가 각자 SA를 가지고 연결된다. 그림의 NOTE 2에 따르면 노드 옆(tractor ECU는 두 노드 사이 위쪽)의 작은 숫자는 CF를 담은 ECU의 번호이고 그 반대편 숫자가 CF의 주소다. 따라서 tractor ECU 위쪽의 7은 주소가 아니라 ECU 번호이고, tractor ECU는 두 세그먼트에 노드를 하나씩 두되 주소는 240 하나로 표시된다.

네트워크 세그먼트 (6.6)

ISO 11783은 2개 이상의 네트워크 세그먼트를 지원하며 기본 구분은 다음과 같다.

세그먼트역할
tractor network트랙터(또는 1차 동력 유닛)의 구동계·섀시 제어와 데이터 통신
implement network작업기 상호 간, 그리고 작업기와 트랙터(주 동력 유닛) 간 제어·데이터 통신

두 세그먼트의 연결에는 tractor ECU가 필요하다.

Tractor network는 트랙터 제조사가 관리하는 세그먼트다.

  • 구동계·섀시의 CF 간 제어·데이터 통신을 제공한다.
  • 물리 계층은 ISO 11783-2 준수가 권장 사항이다(트랙터 내부망이므로 강제가 아니다).
  • 트랙터 네트워크와 작업기 네트워크 모두 트랙터에 온보드로 통합될 수 있다.
  • 트랙터 제조사의 동의 없이는 외부 CF를 트랙터 네트워크에 접속하지 않는 것이 원칙이다.
  • 사용 메시지: ISO 11783-8(구동계)·-7(작업기 응용) 응용 메시지 및 -3의 proprietary 메시지.

Implement network는 작업기 간, 그리고 트랙터-작업기 간 통신을 지원하도록 설계해야 하는 세그먼트다.

  • ISO 11783의 해당 요구사항을 만족해야 한다(shall). 트랙터 위와 작업기 위에 걸쳐 존재한다.
  • 물리 계층 커넥터는 ISO 11783-2를 준수해야 한다.
  • 응용 메시지는 ISO 11783-7에 정의된다. 구동계 메시지(ISO 11783-8)도 작업기 네트워크의 CF 주소로 사용할 수 있다.

전용 ECU 기능 (6.7)

Virtual terminal (6.7.1)

VT는 표준화된 메시지를 사용해 작업기 또는 트랙터의 운전자 인터페이스를 제공한다. 요구사항은 ISO 11783-6에 규정된다. VT는 작업기 네트워크에 접속되며, tractor ECU나 작업기 네트워크에 연결된 트랙터 내부의 다른 ECU도 작업기 working set과 동일한 방법으로 VT를 이용할 수 있다. 즉 트랙터 기능도 작업기와 같은 자격으로 VT 화면을 쓴다.

Tractor ECU (6.7.2)

트랙터 네트워크와 작업기 네트워크 사이에는 전기적 격리와 메시지 격리를 모두 보장하는 network interconnect unit을 두어야 한다(shall). 두 네트워크를 모두 갖춘 시스템에서 그 역할을 하는 것이 tractor ECU(또는 유사 유닛)다.

  • 작업기 네트워크의 implement control function이 보내는 ISO 11783-7 메시지 요청을 수신·해석한다.
  • 해석한 요청을 트랙터 네트워크의 ECU들과 통신하여 처리한다.
  • 요청·명령한 ECU에게 적절한 acknowledgement 또는 응답을 제공해야 한다.
  • ISO 11783-9에 따라 기본 정보(basic information)를 제공하고 명령 메시지에 따라 동작해야 한다.

정리하면 tractor ECU는 게이트웨이이자, 작업기 측에 트랙터 정보(속도, PTO, 히치 등)를 표준 형태로 노출하는 대리자다.

Task controller (6.7.3)

TC는 ISO 11783 네트워크를 통한 작업기 기능의 스케줄 기반 제어를 제공한다. 동작 흐름은 다음과 같다.

  1. FMIS 인터페이스로 수신한 작업(task) 데이터를 TC에 저장한다.
  2. TC가 작업을 스케줄링하고, 실행 대상 CF에게 작업기 네트워크로 제어 메시지를 보낸다.
  3. 작업 수행 중 CF들로부터 받은 데이터를 기록한다.
  4. 기록된 데이터를 작업기 네트워크 상의 FMIS 인터페이스를 통해 FMIS로 전송한다.

TC의 동작과 CF와 주고받는 메시지 형식은 ISO 11783-10, 메시지에 쓰이는 데이터 요소의 정의는 ISO 11783-11의 data dictionary에 규정된다.

Farm management computer interface (6.7.4)

작업기 네트워크는 농장 관리 컴퓨터로의 게이트웨이를 포함할 수 있다. FMIS 쪽 게이트웨이의 물리 인터페이스는 ISO 11783이 규정하지 않는다(자유). FMIS의 파일에서 유래한 데이터를 FMIS 인터페이스에 제공할 때는 ISO 11783-10에 정의된 메시지를 사용해야 한다.

공통 서비스 (6.8 ~ 6.14)

절주제내용 요지
6.8Diagnostics네트워크 오동작의 고장 원인 파악에 사용할 메시지를 ISO 11783-12가 규정한다. 해당 메시지는 참조되는 다른 진단 표준들에도 규정되어 있다
6.9File server데이터 파일 저장소를 제공하는 CF와, 다른 CF가 그 파일을 읽고 쓰는 데 사용할 명령 집합을 ISO 11783-13이 규정한다
6.10Sequence control트랙터 또는 임의 CF의 운전자 조작 기능 시퀀스를 여러 개 기록해 두었다가 운전자 명령으로 재생하는 메시지를 ISO 11783-14가 규정한다. headland management(두렁 선회 관리) 같은 제어 시스템이 대표 사례다
6.11Process dataprocess data 메시지는 TC에서 1개 이상의 CF로 데이터를 전송하는 데 쓰이며, 작업기 네트워크의 다른 CF로 데이터를 보낼 때도 쓸 수 있다. 메시지 구조는 ISO 11783-10, 데이터 정의는 isobus.net의 data dictionary
6.12Working sets특정 애플리케이션에 연관된 CF 집합을 네트워크에 알리는 메커니즘. working set의 정의, 운영 규칙, 수립 메시지는 ISO 11783-6과 -7에 규정
6.13Safe mode operationVT·auxiliary controller·TC로 보내는 정보·제어는 이 표준에 따르되, 거기서 요청되는 제어가 관련 안전 표준에 맞게 설계·제작되었음은 제조사가 보증해야 한다. 컨트롤러가 제공하는 기능은 의도한 효과가 발생하되 상해 위험으로 이어지지 않도록 설계해야 한다. 추가 safe mode 요구사항은 ISO 11783-9
6.14파라미터·메시지 추가작업기-트랙터 통신 메시지는 -7, 트랙터 구동계 메시지는 -8에 규정. 특정 응용을 위한 메시지 집합을 ISO 11783에 추가할 수 있으며, 신규 코드 추가·갱신 요청은 데이터베이스에 게시된 code request form으로 유지관리 기관(MA)에 제출한다

안전 책임의 소재

표준은 통신 방법만 정의한다. VT·보조 조작기·TC를 통해 원격으로 구동되는 기능이 안전 표준에 부합하는지, 오동작 시 상해로 이어지지 않는지는 전적으로 제조사 책임이다. 이는 6.13과 ISO 11783-9의 safe state 개념(시스템 일부가 고장 나도 허용 가능한 위험 수준을 유지하는 운전 모드)으로 뒷받침된다.

ISO 11783-1 전자 데이터베이스 (Clause 7)

parameter group·address·identity 할당을 담은 전자 데이터베이스는 isobus.net에서 접근한다. 모든 항목은 SAE J1939에 공식 등록된다. 데이터베이스가 제공하는 현행 목록은 다음과 같다.

실무 포인트

ISO 11783 스택을 구현할 때 NAME의 manufacturer code, function code, industry group 값과 preferred address는 이 데이터베이스에서 조회·신청한다. 신규 PGN·주소·identity 할당이나 기존 항목의 설명 갱신은 Annex A가 안내하는 대로 isobus.net의 request form으로 신청하며, ISO/TMB가 지정한 유지관리 기관(MA)이 처리하고 SAE J1939 위원회와 코드 등록을 동기화한다.
